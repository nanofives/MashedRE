# TUs compiled with /arch:IA32 (x87) instead of MSVC's default /arch:SSE2.
# Consumed by build_objs.ps1 -X87List (see build.bat). One TU basename per line.
#
# WHY. These are verbatim transcriptions of x87 instruction streams. Under the default
# /arch:SSE2 a `float` expression rounds to 32 bits after EVERY operation, while the
# original holds intermediates at 80 bits in the x87 stack and rounds once at the FSTP;
# `float10` (= long double = double on MSVC) is likewise a 53-bit mantissa in SSE2 rather
# than an 80-bit chain. Two TU header comments used to assert "Build is x87 (no
# /arch:SSE2)" -- there was NO /arch flag anywhere, so the opposite was true. Full
# measurement: re/analysis/float_model_is_sse2_not_x87_20260910.md, decision D-11070.
#
# THE LIST IS MEASURED, NOT REASONED. A 10-TU trial (the pilot below plus the 9 TUs holding
# the 15 remaining DIVERGENT* rows) was run over all 47 affected rows at --group 1, and the
# result did NOT generalise from the pilot: 4 divergences fixed, but 7 new CRASHes and 3
# VOIDs, 6 of them on rows that had been CLEAN. Attributing every outcome to its TU showed
# the benefit and the damage are cleanly separated, so the list is now exactly the TUs where
# /arch:IA32 demonstrably pays with zero damage:
#
#   TU                      fixed  held  still-div  CRASH  VOID
#   RwpSolverBroadphase3        2     2          0      0     0   <- pilot, measured alone
#   RwpSolverCore17             2     1          2      0     0
#   RwpSolverCore14             1     2          1      0     0
#   RwpSolverCore15             1     0          0      0     0
#   ------------------------------------------------ KEEP: 6 fixed, 0 regressions
#   RwpSolverCore16             0     2          2      0     0   dropped: buys nothing
#   RwpSolverCore18             0     4          0      1     0   dropped: damage
#   RwpSolverCore19             0     1          0      1     0   dropped: damage
#   RwpSolverCore20             0     1          0      1     0   dropped: damage
#   RwpSolverCore23             0     7          0      3     0   dropped: damage (2 were CLEAN)
#   RwpSolverLeaves1            0     8          2      1     3   dropped: damage (4 were CLEAN)
#
# [UNCERTAIN] whether the dropped TUs' CRASHes are port or witness problems is NOT
# established -- they were armed runs with no `--no-shadow` control. It does not change the
# decision: those TUs show no benefit and measurable damage, so they are excluded. If anyone
# wants them, run the control first.
#
# PER-TU, NOT GLOBAL, deliberately: /arch:IA32 would otherwise disable SSE2 for librw (the
# shipping renderer, gate D2) and every non-physics TU -- a broad performance and codegen
# change with no measured benefit outside the physics lane. The 10-TU trial is also the
# evidence that a blanket application would have been WRONG.
#
# CAVEAT that limits what this can buy: /arch:IA32 does NOT make `long double` 80-bit --
# that ABI is fixed in MSVC -- so only register-resident intermediates recover the extra
# width. A NAMED `float10` local still stores 64 bits.
#
# TO ADD A TU: measure it. Run its rows before and after, keep it only if it fixes something
# and regresses nothing. The list's content is part of the object-cache flag stamp, so an
# edit here forces a full rebuild of both targets.
