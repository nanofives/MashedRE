## Why v4 exists

v3 used one ladder for two different questions. A row reached C4 only when `mashed_re.exe` used the
matched or verified body, called it (L-68) and kept the gates unchanged. So C4 measured the port, and
reverse-engineering work that was already complete did not show up. The survey of 2026-11-07 behind
L-93: **1,796 of 2,157 attempted game functions match the original 100%**, but only 175 of them were
C4 (59 by match), 322 were swapped into the exe with no caller, and about 1,357 were never swapped.
**462 library functions are identity-matched** (Lua, qhull, CRT), with 0 at C4.

SimGolf already separated the two (`SimGolf/re/PORT_PLAN.md`, "C4 stops being the gate",
`SimGolf/re/C4_PLAN.md`). v4 does the same for Mashed, in Mashed's form (L-93 option B):

- **RE axis.** C0..C4 says how well the original is understood. **C4 = reverse engineering
  certified**: a 100% byte match (relocheck OK, not a naked inline-asm transcription) or library
  identity is C4 on its own. The rule text lives in [`re/CONFIDENCE.md`](re/CONFIDENCE.md), owned by
  step C4R-RUBRIC. This file does not restate it.
- **Port axis.** What `mashed_re.exe` runs. Tracked in a derived `hooks.csv` column `port`
  (`none` / `body` / `called`, regenerated by script, step C4R-PORTCOL) and by the playthrough and
  default-build gates. Port facts no longer gate C4.

L-93 supersedes the C4 parts of L-68, L-73, L-84, L-89 and the libid port-use clause. CRT, libpng and
zlib stay out of the P-DoD port count (L-67 / L-70) but may carry C4 by library identity.

**The project's Definition of Done is the port axis.** v1.0 ships on P-DoD (port). The RE axis has its
own completion target and does not gate v1.0.

## The default-build rule (kept from v3)

> **A port capability counts only if it runs in `mashed_re.exe` with no `MASHED_*` variable set.**

1. Env vars are for verification, bisection and debugging, never for selecting which implementation ships.
2. A port is landed when its path is the default. A flag may only turn it off for A/B.
3. Every port-axis gate is measured on a clean environment (D-Gate). A demo that needs a flag does not count.
4. A behaviour change ships as a default-OFF knob plus a committed PREREG. The flip is a user decision row.

The rule applies to the port axis only. It never applied to C-levels, and after L-93 nothing on the RE
axis depends on the exe. Full v3 text: archive, "The default-build rule".

## Definition of Done

### RE axis

- **F-DoD (RE).** The row is C4 under [`re/CONFIDENCE.md`](re/CONFIDENCE.md) (byte match, library
  identity, or any other route that file lists for code that cannot match). RVA pinned, analysis
  note or match record cited, no unfiled `[UNCERTAIN]`.
- **S-DoD (RE).** Every row of the subsystem is C4, or has an open M5 row that names its route (near-miss,
  compiler, platform glue, Frida). Structs it uses are documented. No C3-blocking `UNCERTAINTIES.md` row
  without a resolution path.
- **P-DoD (RE).** Every game row is C4 or carries an M5 route. Every library row is C4 by identity or
  carries its waiver status (`waived-platform-crt`, `waived-library`). The match ledger
  `re/analysis/match_ledger.tsv` is current (C4R-MATCHBATCH-2).

### Port axis (the project DoD)

- **F-DoD (port).** `port = called`: the exe has one body for the RVA (`scripts/lint_rva_bodies.py`
  clean) and the default build calls it. The behaviour evidence covers **the exe copy**
  (`re/CONFIDENCE.md`, "Which copy the evidence covers"): a byte-matched body swapped in verbatim, or a
  clean `diff-original` / parity-harness result on the shared body. Default gates unchanged, or a decided
  flip with new refs in `merge_train.json`. Inline RVA comments, runtime-toggleable on the `.asi`.
- **S-DoD (port).** v3's six criteria, read on the port column:
  1. no fallbacks, env-gated alternatives included. A subsystem whose port runs only under a flag is not done.
  2. every function the default build executes meets F-DoD (port).
  3. functions it does not execute are dispatched explicitly (`DEFERRED.md` or `wontfix`).
  4. structs documented.
  5. formats the game **writes** round-trip (`gamesave.bin`, `videocfg.bin`, `contcfg%d.bin`, AI path
     data from `FUN_00423540`). Parse-only formats need parse coverage only (L-22 (a), full list in the
     v3 archive, "Criterion 5 scope").
  6. the subsystem's `STUBS.md` section is empty.
- **P-DoD (port).** Every subsystem S-DONE (port). `re/tools/dual_copy_allowlist.txt` empty. A clean
  playthrough of every track, vehicle and mode on `mashed_re.exe` alone. Trackers empty but for justified
  `wontfix` / `deferred-not-needed`. Dev `.asi` out of the shipping matrix. Multiplayer (WS-I) is out of
  v1.0 scope (`DEFERRED.md` D-11063). CRT, libpng and zlib are outside the port count (L-67 / L-70).
- **D-Gate.** Every port phase demo runs on a clean environment: no `MASHED_*`, no manual step.

No port-axis line reads the C-level, and no RE-axis line reads the `port` column.

## How the work runs

- **Ledger:** `log/orch/roadmap.json`, one live file, written only through
  `re/orchestrator/roadmap.ps1`. Worker rules: `re/orchestrator/WORKER_RULES.md`. Conductor:
  `.claude/skills/roadmap-loop/SKILL.md`. Decisions: `log/orch/DECISIONS.md`.
- **Gate refs:** `re/orchestrator/merge_train.json` is the only source. A hash-changing change is a decision row.
- **Trackers:** only through `re-classify`. Session kickoff: `re/NEXT_SESSION.md`. Standing harness work:
  `re/HARNESS_BACKLOG.md`.
- **Process rules carried from v3** (archive, "Process rules adopted 2026-08-14"): branch teardown with
  `git branch -d`, worktrees removed only with `py -3.12 scripts/diag.py wt-remove`, cited evidence is
  committed (summaries, not raw arm data), append-only trackers are never overwritten.
- **Workstreams WS-A..WS-J** are no longer tracked here. Their last status table is in the v3 archive,
  "Workstream ledger".
