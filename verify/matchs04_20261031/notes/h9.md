# MATCH-S04 helper h9 notes (2026-10-31)

Findings worth reusing:
- DAT_0063d9e0 is an array of 0x2ac-byte (0xab-dword) per-player records. Ghidra's DAT_0063dc38/3c/40/4c/6c/7c
  are record offsets (+0x258 pos V3, +0x26c obj, +0x29c car). Taking `PSlot *s = &DAT_0063d9e0[i]` into a local
  reproduces the separate `add eax,0x63d9e0`; indexing the array directly folds it away.
- The (p1*0xab + p2) table reads want the entry in a local `int *` (0x0041f290, 0x0041f1e0).
- 16-dword matrix copies (rep movsd) are struct assignments.
- cl 13.00 keeps parenthesised FP association: `(y*y + x*x) + z*z` (0x0041f120), `((float)dt * k) * rate` (fimul, 0x0041f3d0).
- Float literals vs MGLOBAL floats are NOT equivalent: `x += 360.0f` emits fld [x]; fadd k, `x += g` emits
  fld g; fadd [x] (0x0041f3d0). A literal compare bound also lets cl fold the clamp branches (0x0041f590).
  relocheck checks literal values (__real@), so literals cost nothing.
- Operand order picks local stack slots: `(a.z + b.z)` vs `(b.z + a.z)` swapped the slots of a and b (0x0041f4f0).
- 0x00420870 calls 0x0041f3d0 (stack), 0x0041f4f0 (EDI), 0x0041f590 (ESI), 0x0041f710 (EAX): one TU with static
  callees. A two-call stand-in caller was enough for cl to pick EDI / ESI (0x0041f4f0, 0x0041f590); 0x00420230 is
  the caller of 0x0041f330 (ESI).
