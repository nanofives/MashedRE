# PREREG RWC-CORE-RUN: RW engine bring-up on the matched RW core (L-124 (C) step 2)

Committed alone, before any arm. Branch `orch/RWC-CORE-RUN`, stacked on `orch/RWC-DEVICE` 7b64f91ea and
`orch/RWC-DRIVER` 29a753e89 (the 0x004c7a70 source).

## Change

Knob `MASHED_RWC_CORE=1`, default OFF, consulted only on the `MASHED_ORIG_TOP=1` path (LibRw/RwApiBind.cpp engine
bindings, `RwCore_Enabled()`). With it ON, the engine calls of the matched bring-up 0x00493710 run RW core bodies
(`mashedmod/src/mashed_re/RwCore/`, generated by `gen_rwcore_tus.py` from re/match sources) instead of librw:
RwEngineInit 0x004c32b0, RwEngineOpen 0x004c30b0, RwEngineStart 0x004c2fb0, Stop / Close / Term, and the driver
setters 0x004c9f50 / 0x004c9eb0 / 0x004c9f60. The D3D9 object comes from the RW driver 0x004c7a70 through
`RwCoreHand_Direct3DCreate9` -> `MashedD3D9Wrap_Direct3DCreate9`. RenderwareAttachPlugins 0x00493640 does nothing on
that path. After RwEngineStart the knob logs a probe, stops the engine on the core and returns 0, so 0x00493710 runs
its failure path and the boot ends (the rest of the top-down path still calls librw and the hand frame).

Default path: unchanged code except `RwApiBind.cpp` (each changed binding first evaluates `RwCore_Enabled()`, false
when the env var is absent) and the new exe TUs (not called with the knob OFF).

## Reading

- GREEN for the row's exit: first menu frame rendered by the RW core with draw calls compared to the original. This
  row does not reach it by construction (the frame on the top-down path is the hand stand-in, PortTop_HandRenderFrame,
  `Match/PortTop_00492370.cpp:240-247`); see the RESULT for the remaining steps.
- The bring-up is read step by step from the `[RWC_CORE]` lines: RwEngineInit result and RwGlobals = 0x007D3EC8,
  RwEngineOpen result and IDirect3D9 [0x007d4108] nonzero, RwEngineStart result and device [0x007d4110] nonzero,
  texture-module freelists at RwGlobals + [0x007d4054] + 8 / + 0xc nonzero, Stop / Close / Term results.
- A `STOP: rva 0x... called` line names the first missing body. An access violation is read from the crash dump /
  exit code. Either is the first failing step.
- Knob OFF: the `[ORIG_TOP]` / `[RW_BIND]` log equals the parent row's (no default-path change).
