## 1. Method

- Input: `verify/matchlint_20261115/lint.tsv` (MATCH-CALLEE-ARITY-LINT), regenerated in full with
  `py -3.12 re/tools/match/callee_arity_lint.py --out <scratch>/lint_full.md --tsv <scratch>/lint.tsv` (same tool, same tree).
- "Compiled into the exe": the offending source is `#include`d by a file under `mashedmod/src/` (1918 distinct
  `re/match/**/*.c` are). Of the ARITY callees with an own-source reference, **347 (callee, offending source) pairs** have
  their offending source included. The wrapper path per pair is in `triage.tsv` column `wrappers`.
- Original side, read from `original/MASHED.exe.unpatched` (SHA-256 anchor) with capstone, function extents from
  `re/console/pc_funcs.csv` (`body_end` inclusive). No Ghidra MCP on claude2. Per pair:
  1. callers = the functions the offending source defines (`MATCH:` tags, definitions, file name RVA);
  2. every direct `call`/`jmp` to the callee inside them; the pushes between the previous call/branch and the call
     (frame-prologue pushes dropped), the instruction after the call (`add esp, N` cleanup check), and whether the pushed
     dwords are released before the next call (and if not, whether the next callee reads them);
  3. callee side: `ret` immediates (all `ret 0` here, so every callee is caller-cleans) and the highest stack-argument slot
     it addresses (linear esp-tracking scan over the body, `lea` excluded), plus tail `jmp`s out of the body and what the
     jump target reads.
- Declared sizes are counted in **dwords** (struct-by-value parameters expanded from the source's typedef), because the
  lint counts parameters and `Rect{x,y,w,h}` vs `V2,V2` is the same 4 dwords.
- Scripts and full data: `verify/MATCH-ARITY-TRIAGE-1/triage.py` (pairs and sites), `gen.py` (tables + the hand-read
  overrides, each with its addresses), `xcalls.py` (all direct callers of an RVA), `odis_x.py` (range disassembly),
  `triage.tsv` (one row per call site, 421 site rows).
