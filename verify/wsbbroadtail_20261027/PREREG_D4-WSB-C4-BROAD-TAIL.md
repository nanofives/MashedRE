## Row and static facts (anchored image, `tail_disasm.txt`, SHA-256 prefix `BDCAE093A30FBF22`)

`0x0055ae50` (C3/impl, `RwpSolverBroadphase3.cpp`): loads `[esp+8]` (`0x0055ae50`) and `[esp+4]` (`0x0055ae54`),
`mov cx, word ptr [eax+0x20]` (`0x0055ae58`), `mov eax, [edx]` (`0x0055ae5c`), writes the param_2 slot (`0x0055ae5e`)
and the param_1 slot (`0x0055ae62`), then `jmp 0x00565550` (`0x0055ae66`). No `call`, no `ret`, no other store.

`0x00565550` (the tail callee): reads both slots (`0x00565550`, `0x00565554`), `and eax, 0xffff` (`0x00565558`),
`mov ax, word ptr [ecx+eax*2+0xb810]` (`0x0056555d`), `ret` (`0x00565565`). No store. param_2 is read only through the
`and eax, 0xffff`, so bits 16-31 of the incoming param_2 are not read. In `0x0055ae50` those bits are the caller's ECX
bits 16-31 (only CX is loaded at `0x0055ae58`); the port passes the zero-extended `ushort`
(`FUN_0055ae50_impl`, `movzx eax, word ptr [eax+0x20]` at `.asi` `0x1005f4d4`). This is the proof for the mask below.

So the whole call tree of `0x0055ae50` writes exactly 2 dwords, both in the caller's frame (entry slots), and nothing
else. The scope note found no caller that reads those slots back (`argslot_callers.txt`, 5 direct callers).

The port body: `FUN_0055ae50_impl` = `push movzx(param_2+0x20)`, `push *param_1`, `call _FUN_00565550`, `add esp,8`,
`ret` (`.asi` `0x1005f4d0..0x1005f4e7`). The impl reads no `NarrowFixKnobs` static, so the RunTracked warm-up issue seen
by D4-WSB-C230-RECHECK (`7845651a4`, not an ancestor of this branch) does not apply.

## Decision rule

- **R**: pass = `C4-CLEAN` (OFF and ON signature sets equal and non-empty, ON byte `0xE9`). The OFF side must show the
  tail jmp as a `[c565550,...]` call-out (that is what the tool change is for). Predicted: one or more
  `[c565550,A0@0,<k>] ax=<v>` signatures on both sides.
- **H**: pass for the write-set leg = 24 samples, ndiff 0, `A/B-IS-REAL installed=e9`, no NOISY / UNTRACKED / OTHER-EXC
  line, **and heap pages compared > 0** (L-38).
- **C4** only if G, R and H all pass. Promotion and any note go through the re-classify skill.
- **Predicted outcome**: H compares **0 heap pages** (the static facts above leave no heap or image store in the call
  tree), so `0x0055ae50` **stays C3**, with a dated re-classify note naming the blocker: its write set is 2 caller-frame
  slots, compared by the 4 KB stack window, and L-38 / L-40 keep it at C3. If H instead shows heap pages > 0, the
  static read above is wrong and the RESULT reports which pages and from which instruction before any promotion.
- No NEED_PAGES arm: with no store outside the caller frame in the call tree, it cannot count a sample (BROAD-WS's
  `0x0055bae0` / `0x0055c000` NEED arms gave NO-WRITES-SAMPLED for the same shape).
