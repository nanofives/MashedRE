
`eip=0x00000044` with `ebp=0` = a call through a **near-null function pointer** (field at +0x44 of a
null/garbage object). The return chain is dominated by the **CRT band** (`0x004a4bb7` = `entry`,
`0x004a4bcf`, `0x004a4d38`, `0x004a4d60`, `0x004ac660`, `0x004abbe5`) → the fault happens during
**CRT startup / static-init**, before the game's own main loop. This matches the
`project_boot_crash_static_init_not_heap` class, not the menu/RW-asset framing.

## Corrected observation about exit codes (this misled the first hour)

`Start-Process -PassThru` reports `ExitCode = -1` (0xFFFFFFFF) for this crash, which CLAUDE.md's
multi-session note describes as the *force-kill* signature. Using `WaitForExit()` before reading
`ExitCode` yields the true **`-1073741819` = 0xC0000005**. Anyone triaging a boot failure must
`WaitForExit` first, or they will misclassify an AV as a clean exit and follow the wrong branch of
the decision tree (as happened here).
