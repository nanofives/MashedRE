### #4 is the one worth remembering

`FUN_004b40c0` loads `MOV EAX,[EDX+0x24]` (the count) at `0x004b40c4` **before any branch**, and no
path afterwards clobbers EAX (loop counter is ECX, scratch is EDI) — so it **implicitly returns**
the count at the `RET` at `0x004b40e7`. That value survives the tail-JMP adjustor `0x004b4130` and
the wrapper `0x004b4140`, and the sole caller `FUN_004b5260` consumes it at `0x004b5281`
(`MOV ESI,EAX`) as the trip count of the loop at `0x004b52a3..0x004b52af` — whose store sits at
**`0x004b52ac`, the dump's exact faulting EIP**.

> **Rule:** `void` is safe only when the original's EAX is provably dead at every `RET`. An original
> that merely *leaves* a useful value in EAX has an implicit return callers may depend on.

### The fix shape for register-arg originals

Keep the C body's stack ABI (so `re/frida/hooks_registry.py` keeps driving the export unchanged) and
register a naked marshalling shim instead:

```cpp
extern "C" __declspec(dllexport) __declspec(naked) void __cdecl Find42ad90_RegAbi(void) {
    __asm { push edi ; push ebx ; push edx ; call Find42ad90 ; add esp, 0Ch ; ret }
}
RH_ScopedInstall(Find42ad90_RegAbi, 0x0042ad90);   // shim installed, NOT the C body
```

EBX/ESI/EDI are callee-saved under `__cdecl`, so the shim preserves what the original preserves; the
return stays in EAX.

still dies) and by skipping both new hooks (still dies). Not caused by this session's work.

**`bisect_hook_index.ps1 -Seconds 16` cannot see it.** Two ways forward:

1. **Dump-first (cheaper).** Archive `%LOCALAPPDATA%\CrashDumps` (10-dump retention cap will
   otherwise suppress the new dump — this artefact already cost one session), let it AV, then
   `py -3.12 scripts/parse_minidump.py <newest.dmp>`. The EIP + ret-chain may name the site directly,
   the way `0x004b52ac` did for crasher #4.
2. **Long bisect (decisive but slow).** `pwsh scripts\bisect_hook_index.ps1 -Seconds 90 -Runs 3`
   — ~12 probes × up to 3 × 90 s ≈ **50 min**. `-Runs 3` is the minimum for a ~75% flaky fault
   (a 2-run probe misses ~6% of the time and silently breaks the search's monotonicity).

> **Measurement rule learned here:** three passing runs is NOT evidence of absence for a ~75% flaky
> fault. State the run count on any survival claim, and use ≥ 4.

## 4. Method notes that still apply

- `pwsh scripts\bisect_hook_index.ps1 -Runs 2` — index-level bisect, **no rebuilds**. Confirm any
  suspect alone with `$env:MASHED_HOOK_ONLY='<name-or-0xRVA>'`; `MASHED_HOOK_SKIP` is the denylist.
  Baseline `MASHED_HOOK_HI=0` boots.
- **Always `WaitForExit()` before reading `ExitCode`** — otherwise this AV reads as `-1`
  (0xFFFFFFFF), which CLAUDE.md documents as the *force-kill* signature.
- **Park BOTH `.asi` copies or set `MASHED_RE_NO_AUTO_HOOK=1`** — `LoadDevAsi()` falls back to
  `mashedmod\build\mashed_re_dev.asi`, so renaming only the deployed copy leaves the hooks live.
- **Expect multiple independent crashers.** Fix one and the crash moves later. Re-run the bisect
  after every fix.
- Kill only PIDs you spawned; never blanket-kill `MASHED` by name.
