`re/tools/gen_naked_asm.py`. Each spec drops the func, maps the `call` to the shared body, and loses the RW-LUT `patch`

Exceptions to bit identity, stated, not measured: PC_24 x87 keeps the 15-bit exponent, so a product or sum that is
subnormal as a float is rounded twice on the x87 copy and once in SSE2. That needs |v| below about 1e-19. The lanes'
non-default knobs `MASHED_*_PC=53|64` (AiLeafTargets, AiTargetClosest, PickupTick, PathProgStep, WorldRegistry) no
longer change these four leaves, since the helpers do not read the x87 precision control.

Compiled exe objects (`dumpbin /disasm`, `D:/MashedWT/D4-DC-INC-batch3_data/dumpbin_exe.txt`): the helpers write
`eax, ecx` and `xmm0..2`, save and restore `esi`, and call the function-local `T()` (cdecl). The originals write
`eax, ecx, edx`. The naked callers are pure x87 and keep nothing in `xmm`. Each helper uses one x87 slot (the result).
The originals use up to 5.

**Residual on 0x004c3ac0 / 4c3b30 / 4c3b90, outside this batch.** These three RVAs still have a second C form in
both targets: the installed C4 hooks `Math/Vec3.cpp:Vec3Magnitude` and `Math/RwSqrt.cpp:FastSqrt / FastInvSqrt`.
The scanner does not bind them (their header comments read `// Original: 0x...`). In the exe they take the
`std::sqrt` fallback (RwLutGuard finds no RW globals), while every naked lane, and now every lane through these
helpers, uses the LUT. Folding them is a behaviour change for the exe's C callers of FastSqrt / FastInvSqrt /
Vec3Magnitude, the same class as Mariano's L-13 / L-14 answers for 0x004c39b0 / 0x004c4680. Recommended follow-up row:
"D4-DC-LUT-C-PAIR: one C form per RVA for 0x004c3ac0 / 4c3b30 / 4c3b90", default-OFF knob + PREREG, then a flip
decision. Tagging the LUT helpers as the one body would have hidden this, so they carry no RVA tag. hooks.csv
`exe_file` names both forms.
