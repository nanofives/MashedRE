## How `called` is decided

The MATCH slices' exe-caller check (`verify/matchs*/tools/exe_reach.py`: direct `E8`/`E9` rel32 edges
from the linker map, BFS from `_WinMain@16`) made whole-program and mechanical:

1. Graph nodes: every public and static symbol of `mashed_re.map` (26,872).
2. Edges: the direct rel32 call/jmp edges exe_reach.py uses, plus every base relocation (60,339): a
   relocated dword is an absolute address, so the symbol holding it references the symbol it points
   into. This is what the direct graph cannot see (window procs, vtables, callback tables).
3. Root: `_WinMain@16` only. The CRT static initialisers are not roots: the exe's no-op
   `RH_ScopedInstall` registrations (`Stubs/HookSystemNoOp.cpp`) live there and take the address of
   every hooked body.
4. L-89 barrier: a symbol whose base name contains `Replay`, `SelfTest`, `Selftest` or `Harness` is
   reached but not walked through (24 reached, `port_report_barriers.txt`). The game's own ghost
   replay (`ReplaySave`, `ThunkReplaySave`) is exempt. L-84: a dev path in the shipping exe
   (Nav_DevGoto) is walked like any other.
5. RVA to symbol: the `rva_body_scan.py` bodies of each exe TU (the `exe_file` source), name read from
   the definition's own signature, MATCH wrappers' `#define FUN_x Name` followed, `match:` include
   anchors resolved through the included source's `// MATCH:` line. Matched to map symbols in
   `<TU stem>.obj` by undecorated base name, else to the one .text symbol with that name.
6. Inlined bodies: the build has no /GL, so a body with no map symbol is inlined within its TU (or
   never emitted). It is `called` when the definition enclosing one of its call lines in the TU or
   its included matched sources is reachable (12 rows, how=`reached/inlined`).

Reachable from WinMain: 13,322 symbols. Of 915 exe-body RVAs, 831 resolve to a map symbol directly,
12 through inlining, 58 stay `body` with no resolvable symbol (how=`unresolved`, listed in
`port_report.tsv`: mostly channel-B audit lines that drifted since 2026-09-29, e.g. 0x00418560
`Ai/AiStandalone.cpp:1600`, and statics with no reachable enclosing caller).

## Limits (stated so the column is not over-read)

- `called` is static reachability in the shipping exe, not execution in the default build. A body
  behind a default-OFF behaviour knob is `called` (the AiLeaf case above). L-84 treats a dev path
  the same way; L-89 only excluded harness paths. Whether default-OFF knob paths should count is a
  question for the port roadmap if it ever needs "executed by default" (that needs a runtime trace,
  not this script).
- A harness written inline in a game function (an `if (getenv(...))` block, not its own function)
  is not seen by the name barrier.
- The column is only as fresh as the build: `backfill_port.py` refuses a map older than the newest
  file under `mashedmod/src`, and refuses when `exe_file` is stale.
- 0x00496900 notes say `exe-callers=1` (ICF-shared with `Pred497450`) but its `exe_file` is empty
  (the body scan finds no exe body for that RVA), so it is `none`. Not changed here: `exe_file` is
  the scanner's.
