### .rdata the chain reads

The exe maps the original data range zero-filled. `gen_dinput_seed.py` writes `PortTop_DInputSeed.inc` from
`original/MASHED.exe.unpatched` (anchor checked): the IID at `0x005d0a8c` (DirectInput8Create) and the keyboard GUID at
`0x005d09ec` (CreateDevice). The keyboard DIDATAFORMAT at `0x005d0974` is **not** copied from the original. Its object
array pointer (+0x14) is `0x0049b5d0`, inside the original code range, which the exe does not map as original data, so
writing those 4096 bytes back would land on exe memory. `PortTop_SeedDInput` copies the exe's own `c_dfDIKeyboard`
(dinput8.lib) to `0x005d0974` instead and checks its header against the original's (`0x18 0x10 2 0x100 0x100`):
equal on the run below.
