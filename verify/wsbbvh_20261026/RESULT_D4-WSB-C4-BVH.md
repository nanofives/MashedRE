### Harness fixes (why the stock tool could not be used as is)

The pilot on `0x0055fe50` read HOLD on artefacts only. Fixes, each in `make_tool.py`'s docstring:

1. **Heap addresses move between boots.** `0x0055fe50` returns `param_1` (`mov eax, esi` at
   `0x0055fe99`) and so does the port, yet EAX read `f1eb0b8` vs `fbfc340`. Values are now encoded
   relative to the target's entry: `A<k>+off` (within 0x4000 above stack arg k, k < declared arity),
   `S+off` (caller frame), `Sloc` (target's own locals), `h<n>` (other mapped address, renamed by first
   appearance in that call), raw hex (anything unmapped).
2. **The port calls its own `.asi` callees** (`0x0055fe50` -> `FUN_0055a1f0` in
   RwpSolverBroadphase3.cpp). `.asi` targets are resolved through `mashed_re_dev.map`
   (`6bb50d00...04ed`): a `FUN_<rva>` symbol reads as `c<rva>`, the original's token.
3. **Wrapper / impl.** Every `.asi` symbol carrying `FUN_<rva>` is the target's range; calls into
   ShadowAB templates for the target's own wrapper and into `__security_check_cookie` are not recorded.
4. **The stock tool compared no call argument at all.** It reads `add esp,N` inside the Stalker
   transform, where the parse fails (`C4_DEBUG_N=1` pilot: `#-1/0` both sides of the 10-arg call at
   `0x0055fe91`). Re-read at callout time, cap 16 (stock 8). When the callee is a port with one
   consistent declaration, or the ON boot saw the port's own `add esp,N`, both sides use that count
   (ON runs first): the original defers stack cleanup at some sites (`0x0055ff90` -> `0x00567c60`,
   `0x00560260` -> `0x0056e680` read 0 args OFF, 10 / 16 ON).
5. **Inlined callee wrappers.** `0x00564c80`'s impl calls `RunTracked<void(int,float*,ushort)>`
   directly for `FUN_005646c0` (`.asi` `0x100586f6`). A template call from the target's range is
   recorded as `c<Counter.rva>` with the params after the 2 / 3 / 4 leading template args
   (ShadowAB.h:223/280, ShadowTrack.h:647). Static check: of the 22 bodies only `0x00564c80`'s impl
   calls another function's template, so the earlier CLEAN rows are unaffected.
6. **Return by declared kind** (v4 only): `void` not compared, 16-bit types AX only, else EAX. Each row
   that relies on it has the original's call sites scanned (below). The image's stack probe
   `0x004a3440` (page probe loop, `xchg esp, eax` at `0x004a3450`) and the `.asi`'s CRT `__chkstk` read
   as the same callee.

Tool versions: v3 `b86f2d65...c288` (items 1-4) ran batch 1 row 8 and all of batch 2. v5

### Out-memory leg (lead note 2026-10-26: return-only A/B hid write diffs on NARROW)

The racediff compares call-outs and the return, not memory writes. A row reaches C4 only if its
out-memory is covered one of two ways:

- **A. No store outside its own frame.** Static scan of the original body `[rva, next hooks.csv rva)`:
  no write-access memory operand with a base other than ESP (capstone, with x87 `fst*`/`fist*`
  counted as writes: capstone flags `fstp [mem]` as a read), no string store, and every ESP-relative
  store below the entry ESP. Then calls + args + return are the body's whole effect:
  `0x0055fe50`, `0x0055ff70`, `0x00561c50`, `0x00561e60`, `0x00561e80`, `0x005641b0`, `0x00565550`.
- **B. Write-tracked shadow A/B with the hook installed** (`run_shadow.py`): `scenario_launch.py
  --track 0 --mode 10 --cars 4 --hold 60 --hooks 0x<rva>` (the census scenario), `MASHED_SHADOW_AB=1`.
  These ports use `ShadowAB::RunTracked` (page-level write tracking of every page the call writes plus
  the caller's 4 KB stack window, pre-state restored between original and port, Core/ShadowTrack.h),
  so writes are compared on identical input at the real call site. All 6: 24 samples, 0 divergent,
  patch-byte proof `A/B-IS-REAL installed=e9`: `0x005601f0`, `0x00560260`, `0x00563f60`,
  `0x00565120`, `0x005646c0`, `0x005651b0` (`shadow_summary.tsv`).

Rows whose body stores but whose C3 shadow is `ShadowAB::Run` (return only) had no write-set compare
in this step and stay C3: `0x0055fea0`, `0x0055ff90`, `0x00561040`, `0x00561390`, `0x00564040`.

## Scope and limits

- 6 samples per row, the first 6 calls after A4 call 300 in one Quick Battle. Most rows show 1
  signature, so one input path per function is exercised. Branch coverage is that of the scenario.
- Out-memory: see the out-memory leg. Category A rests on a static store scan (a store reached only
  through a computed jump outside the linear walk would be missed). Category B compares writes in the
  census scenario, the racediff in Quick Battle, so the two legs are two scenarios, both canonical.
- A row with no call in the sampled path (`0x005601f0`, `0x00563f60`, `0x00565120`, `0x005651b0`,
  `0x005641b0`, `0x00565550`) has only its return in the racediff. For the `void` ones that return is
  not compared (v5) or matched in full (v3), and its effect is carried by the write-set leg (B) or by
  having none (A).
- Every ON boot ran past the window end (A4 call 1204-1228), so the game survived each port.
- `h<n>` and `Sloc` keep only the equality pattern of those values, not the values.
- No injected-fault negative control was run. The comparator is not vacuous on this data: before the
  fixes it reported real call-shape differences (raw heap EAX, the asymmetric arg counts in item 4, the
  missing `c5646c0` call in item 5), and after them `0x00565260` still differs on its EAX (below).
