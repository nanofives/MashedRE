Observations for "is 13.00.9176/9178 enough":
- 3 of 4 reach 100% with 9176/9178. The 4th has only one residual (regs and ops are both 100%).
- Ghidra `extraout_*` register inputs (0x00430290) are NOT link-time codegen. A plain-.obj compile with 9176 reproduces them once the 20-byte callee is defined earlier in the same TU (cl 13.00 intra-module register-usage tracking). Callee after the caller gets inlined (57%). A static callee also gets a register argument (66%). Defining a far-away callee (0x0047ce40) in-TU breaks 0x004715a0 (31.6%), so this is a TU-membership signal.
- The callee has to stay out of line under /O2: either `__declspec(noinline)` or the TU was built with /Ob1. Both give 100%. Worth checking against other files to see whether /Ob1 is the real flag.
- The only (a) candidate is the reg+reg address operand order at 0x00475a3f/0x00475a47. If 9466 is decisive anywhere, this is a place to test it.
- Tooling: match.py takes the Ghidra body size as the linear length, which truncates any function with internal alignment padding (0x004715a0 lost 21 B). Scored here with a scratch wrapper that passes size=0x1dd to `match.score_function`.

Side result: 0x00474db0 (42 B) and 0x0042a920 (20 B) also matched 100% as by-products (the 0x0042a920 MATCH line is in a3_00430290.c; 0x00474db0 was matched in a scratch file only and is not saved in the output).
