Observations for "is 13.00.9176/9178 enough":
- All 5 assigned functions plus 2 neighbours (0x004223f0, 0x0041cb80) are byte-exact with cl 13.00.9176 / c2 13.00.9178. No residual needs 13.00.9466.
- The register conventions (ESI in 0x0041c380, EAX/ECX in 0x004223f0) are not /GL. cl 9176 makes them for a `static` function defined before its caller in the same TU. A non-standard register input in Ghidra (`unaff_ESI`, `in_EAX`) points to a static callee in the same file, not to LTCG.
- File-static globals matter for scheduling: with `static int DAT_0063cde4` the compiler hoists its loads above stores through a pointer, and with `extern` it cannot. A load placed above an aliasing-looking store is a signal that the global is file-static. Check that every .text reference to it falls inside one TU's address range (0x0063cde4: 3 refs, all in 0x0041c380 / 0x0041cb80).
- Block-layout diffs (0x004260e0 at 98.1%, 0x0042b310 at 95.6%) were also source shape (ternary, switch). A goto to a tail block is laid out inline again, so block order in the source is not evidence.
- The g2s starting points (10-57%) had the wrong shape every time (merged temporaries, `||` chains, literal vs array, extern vs static). Rewriting from the disassembly was faster.
