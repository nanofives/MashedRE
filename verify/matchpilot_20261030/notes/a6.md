## Observations: is 13.00.9176/9178 enough?

1. **My first-pass /GL claim is withdrawn.** The register conventions in 0x00419090 and 0x00498d60 come from
   plain cl 13.00.9176 treating `static` functions defined earlier in the same TU. /GL is not needed, which
   agrees with the Rich header (no prodid 43/44). A /GL build gives the same code, so a match under /GL proves
   nothing about the flags.
2. **TU context drives register allocation as well as conventions.** In 0x00498d60 the callee being static was
   not enough (84.1%, permuter 149 compiles, no gain). FUN_00498d60 itself also had to be static, with its
   callers after it in the file. Only then did the allocator swap which value it hoists (import pointer in
   EBP, wnd reloaded into EBX).
3. **No residual so far needs 13.00.9466.** Four of five are 100% on 9176/9178. The open one (0x0045cd30) is
   source/TU shape. Under a scratch /GL build its head registers matched (n=EBX, slot=EDI, start=ESI), so
   the compiler can produce them.
4. **/Ob1 is needed** wherever a static callee is in the file. Under /O2 alone, small static callees are
   inlined. The game kept 34-B single-caller functions as calls (FUN_0045c820).
5. **The default paths in 0x0045cd30 read uninitialised locals.** They sit in the dead param_1 home slot
   ([esp+0x28]), and our compile matches that.
