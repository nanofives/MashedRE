Observations:
- /GS: a cookie with no visible buffer (0x00403050, 0x00403160) comes from a dead `char buf[N]`, N > 4 (a 4-byte one gets no cookie). Char padding inside a struct local also adds a cookie, so pad big structs (D3DCAPS9 in 0x004034a0) with dword arrays.
- RwRGBA passed by value to 0x00427ad0 / 0x00427e00 (UI text/box calls): the order of the byte stores picks al/cl, write the white colour first.
- DAT_00636b74 (copy of the D3D device) is file-static: all 5 .text refs sit in 0x004034a0 and 0x00403910, so those share one TU (with 0x004036a0, the static blit 0x00403910 calls with EBX/ECX/EAX args).
- Stack slot order follows the order of last use, not declaration or names (0x00403910: swapping the two Release calls fixed the layout).
- Layouts: slots 0x007f1038 stride 0x4c (bytes +9/+0xa), second bank at +16 slots = 0x007f14f8; bonus records 0x00636b88 stride 0x14 x 6 {float bonus, int time, int done, int active, float scale}. match_permute.py exits 1 and skips the walk when round 1 finds nothing.
