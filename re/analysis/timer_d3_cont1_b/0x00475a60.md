## Mechanical description

Flushes a pending-operation queue indexed by `DAT_0x0069160c` (count).

For each slot i = 0..(count-1):
1. Calls `FUN_004b6520((*(void***)0x00691604)[i], (*(int**)0x00691610)[i] * 0x50)` — C1 (input). (indirection corrected 2026-07-27, see below)
2. Sets `DAT_00691614[i] = 0` — clears slot's output/result field.

Reads `DAT_0069160c` fresh each iteration (re-read inside loop).

**CORRECTION 2026-07-27 — one level of indirection was missing above and in line 15.**
These three globals hold POINTERS to the arrays; the original loads the global and
THEN indexes through it:

```
0x00475a70 MOV EAX,[0x00691610] / 0x00475a75 MOV EAX,[EAX + ESI*0x4]   size
0x00475a78 MOV EDX,[0x00691604] / 0x00475a81 MOV EAX,[EDX + ESI*0x4]   ptr
0x00475a8e MOV ECX,[0x00691614] / 0x00475a9c MOV [ECX + ESI*0x4],0x0   result
```

so the calls are `FUN_004b6520((*(void***)0x00691604)[i], (*(int**)0x00691610)[i] * 0x50)`
and `(*(int**)0x00691614)[i] = 0`. Only `0x0069160c` (the count) is a direct int
(`0x00475a60 MOV EAX,[0x0069160c]`; `TEST EAX,EAX`).

The reimpl in `Util/UtilMid.cpp` copied this note's missing indirection and indexed the
globals directly, so `size` read a raw pointer word and `size * 0x50` became a ~223 MB
memset — a live write AV at ~72 s (`memset(0x0cf77ec8, 0, 0x0d57a380)`). Fixed 2026-07-27.

## Notes

- `FUN_004b6520` is classified as `input` in hooks.csv; this caller is timer_d3 callee — subsystem kept as `util`.
- The `* 0x50` scaling on the second argument suggests a byte offset into a 0x50-byte record.
- Queue is drained fully each call; count re-checked each iteration (no stale snapshot).
