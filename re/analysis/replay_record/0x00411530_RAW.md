## ABI

`void __cdecl FUN_00411530(void* param_1, int param_2, float* param_3, int* param_4, int* param_5)`

- `param_1` = replay object pointer. **`hooks.csv` and the plate type this `int`; it is
  dereferenced at 0x0041154a** — the known pointer-param-described-as-int defect class.
- `param_2` = index. Element stride **4**, base offset **0x17c** (`EAX + EDX*4 + 0x17c`).
- `param_3` = `float*` fractional-second out, `param_4` = `int*` seconds out,
  `param_5` = `int*` minutes out.
- Plain `RET` on both paths, no immediate → **__cdecl**.

**The two `[ESP+0x10]` reads at 0x00411541 and 0x00411546 are NOT the same slot.** ESP has moved
−4 and −8 respectively from the intervening PUSHes, so they resolve to the original `[ESP+0xc]`
and `[ESP+0x8]`. Reading them as literal `[ESP+0x10]` would swap two arguments. This is the
Ghidra pre-branch-args pitfall in its stack-displacement form.

## Argument mapping into `0x00411350`

x86 pushes build the callee frame in reverse, so first-pushed = last argument:

| push site | value | becomes TimeFormat's |

| 0x00411540 | `param_5` (minutes out) | arg4 `int* minutes` |

## Null path — prior claim REFUTED

The iter13 handler brief recorded: *"null-path: frac=0 mins=0 secs=unwritten (confirmed)"*.
**That is backwards.** The listing writes `*param_4` (**seconds**) at 0x00411564 and `*param_3`
(**fraction**) at 0x0041156a, and never touches `param_5` (**minutes**).

> null path: **frac = 0, seconds = 0, minutes = UNWRITTEN**

A port written from the brief would zero minutes and leave seconds dangling — the exact
inversion of the original, and invisible to any test that only checks "two of the three are 0".
The A/B must therefore pre-seed all three out-slots with distinct sentinels so "unwritten" is
observable, not merely "not 1".

## "Implicit-ST0 pass-through" — REFUTED

The `hooks.csv` note claims *"implicit-ST0 float pass-through to TimeFormat"*. There is no x87
instruction anywhere in this function. The value at 0x0041154a is moved in **EAX as a plain
dword** and pushed as an integer; `TimeFormat` itself loads it with `FILD` from the stack. See
`0x00411350_RAW.md`.
