## ABI

`void __cdecl FUN_00411350(uint32 param_1, float* param_2, int* param_3, int* param_4)`

- Plain `RET` at 0x004113a6, no immediate → **__cdecl**, caller cleans. Confirmed by the caller
  0x00411530, which does `ADD ESP,0x10` at 0x00411558 after pushing four dwords.
- **No `PUSH` anywhere in the body**, so ESP never moves and `[ESP+4]`/`[ESP+8]`/`[ESP+0xc]`/
  `[ESP+0x10]` are args 1..4 directly ([ESP+0] is the return address).
- **param_1 is `uint32`, not `int`.** `FILD` loads a *signed* int32; the
  `TEST EAX,EAX` / `JGE` / `FADD 2^32` at 0x00411358..0x0041135c is the canonical MSVC
  **unsigned**-int-to-float fixup — a negative signed reading is corrected by adding 2^32.
  Typing this `int` would break for every value >= 0x80000000.
- param_2/3/4 are **out-pointers only**; nothing is read through them except `*param_3` inside
  the normalisation loop (which the function itself wrote at 0x0041137f).
- **No incoming ST0.** ST0 is first *written* at 0x00411354 by this function's own `FILD`.

## x87 stack balance

`FILD`(+1) → `FLD ST0`(+1, depth 2) → `__ftol`(−1, depth 1) → `FILD`(+1, depth 2) →
`FSUBR ST0,ST1`(±0) → `FSTP [EDX]`(−1, depth 1) → `FSTP ST0`(−1, depth 0).
**Balanced; nothing is left on the x87 stack at RET.** The trailing `FSTP ST0` at 0x00411394
exists solely to discard the surviving copy of `v` — it is not a store.

## Why the old reading was wrong

Ghidra emits `extraout_ST0` because it cannot model the `FLD ST0` duplication at 0x00411368
together with `__ftol`'s pop — an artifact of x87 modelling around the callee, **not** evidence
of an incoming argument. Three independent artefacts (plate, iter13 handler brief, `hooks.csv`
note) repeated that reading, and the row was REFUSED for promotion on it in `c3-batch-j-s3`.
Every one of them was written from decompiler output; none quoted a listing. Same defect class
as `0x00482900` (orch-iter17) and the 14 `__ftol` plates (orch-iter20).

**Consequence for harness design:** the proposed `st0_in_float_3out` arg_type — an FLD+JMP
trampoline to load ST0 before the call — is **not needed**. This is a plain __cdecl function
with one scalar and three out-pointers, which `ptr_seed_observe` already covers.
