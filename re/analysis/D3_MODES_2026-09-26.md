### 3.1 What the original does

- `FUN_00411170` (0x00411170..0x004111b5) has no round counter: `FUN_00411600`,
  `FUN_00411ae0`, then `if (FUN_00410d10() == 0) return; if (FUN_00410510() != 0)

  `> 0xb` and `DAT_008a94d0 == 4`. `FUN_0042f500` returns `DAT_0067ea64` (team play).
  `FUN_0040e340` returns `DAT_008a94d0`.
- **The seed that makes this a match length:** `FUN_0040b180` (0x0040b180..0x0040b242):
  `seed = 6`. It becomes 4 when `FUN_0040e340() == 2`, when `== 3`, when
  `FUN_0042f500() != 0`, or when `DAT_007f0fd0` is 1 or 2. It writes the seed to scores
  `DAT_008a94e0..0x008a94ec` and previous scores `0x008a9570..7c`, 0 to `0x008a9510..1c`,
  and `0xfffffc18` (-1000) to `0x008a9500..0c` and `0x008a9520..2c`. It is called at
  0x0040ffb8, directly after the `DAT_008a94d0` count: `MOV [0x008a94d0],EBX` @0x0040ff40,
  `INC` / store @0x0040ffa9/0x0040ffaa once per slot `0..3` whose `*(PTR_005f2770+0x34+i*4)`
  is set.
- Ghidra lists that call site inside `FUN_004111c0` with body `0x0040dd80..0x00411322`, and
  `FUN_004111c0` was entered 4061 times in r10cnt, so it runs per frame. That body is

  `FUN_0040b180` itself was entered **2** times in r10cnt (two races, three rounds), so it

### 3.3 The standalone before this session

`StartMatch(int first_to)` already **ignored** its argument (`TrackRenderer.cpp`, "superseded
by the ported score rules"), so `StartMatch(3)` was dead text. The real divergence sat next
to it:
- scores were seeded **0**, not 6/4. So a 4-car match ran 0 → 12, twice the original's 6 → 12;
- `rc.participants` was the constant 4, not the slot count;
- `rulep_.teams` was **never assigned** (it stayed `false`), so `FUN_0042f500`'s arm of the
  target loop never fired.

### 3.4 The port (this commit)

- `StartMatch()`: no parameter (both call sites updated: `RaceSession.cpp`,
  `exe_main.cpp` `MASHED_ROUND`).
- `SeedMatchScores()` = `FUN_0040b180` on scores and previous scores. `RaceSession::Begin`
  calls `StartMatch` before `SetRaceRule`, and the dev route calls `SetTeamPlay` last, so the
  seed is re-run from `StartMatch`, `SetRaceRule` and `SetTeamPlay`. All three are setup-only
  and run before any award, so the last one sees the final rule, participants and teams, as
  the original's single call does.
- `ParticipantCount()` = `DAT_008a94d0`: 1 + AI cars (max 3), the same predicate UpdateRace
  uses for `RuleEngine::Cars::active`. It feeds `rc.participants` (was 4).
- `rulep_.teams = team_play_` each tick (the live `FUN_0042f500()` read).

## 5. REFUTED + PORTED: the rule-10 countdown IS re-seeded per round

`StartRound` said: "The rule-10 countdown is NOT re-seeded per round (3 back-to-back expiry
rounds observed with a stale timer)". The `seed10` record refutes it. In
`rules_oracle_r10seed2.json`, `FUN_004046a0` exited with `DAT_007f0fe4 = 30.0` at SegmentCheck
call 0 (states 1 and 2, setup), **at call 1050 right after segment end #1, and at call 2206
right after #2**. `FUN_004046a0` (0x004046a0..0x00404818) writes the timer unconditionally
(`30.0` on the default course branch) and rebuilds the 6-entry checkpoint table with every
hit flag `0x00636b90 + i*0x14` = 0. Ported: `StartRound` re-seeds `rulep_.timer` +
`rule10_bonus_` via `Rule10Seed` and clears `rule10_hit_mask_` / `rule10_lap_seen_`.

Not exercised live on the standalone. The `MASHED_ROUND_RULE=10` race (`saC_mashed_re.log`)
ended in round 1 on expiry (`r=-1 timer=-0.02`), the same exit the original takes in r10exp.
A re-seed only shows when elimination ends a round before the timer does.
