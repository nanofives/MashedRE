`RainSetHeadColour` begins at `0x004917c0`.

**It never reads `[esp+4]`.** Unlike its sibling bindings it ignores the `lua_State*`
entirely: it takes no Lua arguments, reads no stack values, and returns 0 (zero Lua
return values). It is a stateless enable.

## What it does

1. `call 0x00490e70` — carries the existing annotation *"[C1 2026-05-14] LineRain parameter
   init — writes all default values to the global rain parameter cluster"* (215 bytes,
   writes `DAT_00616030..37`, `DAT_006146c0..cc`, `DAT_00771538`, `DAT_0077153c`, …).
   So enabling rain **resets every rain parameter to its default first**.
2. `mov dword [0x00771534], 1` — sets the rain-enabled flag.

Ordering matters for a port: the defaults are written **before** the flag is raised, and
`RainSetPosition`/`RainSetScale`/etc. are separate bindings called *after* `RainEnable` in
a course script. Calling `RainEnable` after the setters would silently discard them.

## Lua API identified alongside

`0x004b7090` — `lua_tonumber`. Resolves the stack index via `FUN_004b6ff0(L, idx)`,
returns `*(double*)(p + 8)`, falling back to a conversion helper `FUN_004b7f30` when the
type tag at `p + 0` is not `2`, and to `_DAT_005d1008` when the index does not resolve.
Returns `float10` (x87 80-bit), which callers narrow through `__ftol` (`0x004a2c48`,
already C3).

With `lua_gettop`'s `>> 4` (see `0x0047ad30.md`), this pins the value layout: `TObject` is
**16 bytes**, type tag at `+0`, number at `+8`.

**U-9042 RESOLVED 2026-08-18.** The tag compared against is `2`, and the vendored Lua is
**4.0** — the binary contains `$Lua: Lua 4.0 Copyright (C) 1994-2000 TeCGraf, PUC-Rio $`
at `0x005d8790`, the only Lua version string in the image. Lua 4.0's enum is
`LUA_TUSERDATA 0, LUA_TNIL 1, LUA_TNUMBER 2`, so `2` is `LUA_TNUMBER`. In Lua 5.0 it would
be 3, which does not match. This also corrected 297 `hooks.csv` rows mislabelled
`third-party-library[lua-5.0]` and the `Lua 5.x` claim in `CLAUDE.md`.

## Sibling shape, for the rest of the `Rain*` family

`RainSetHeadColour` (`0x004917c0`) shows the standard argument-reading form:

```asm
mov edi, [esp+0x18]          ; lua_State* (after 5 pushes)
push edi ; call 0x004b6fc0   ; lua_gettop -> esi = argc
lea eax, [esi-3] ; push ; push edi ; call 0x004b7090 ; call 0x004a2c48   ; ftol(tonumber(L, top-3))
lea ecx, [esi-2] ; ...                                                    ; top-2
lea edx, [esi-1] ; ...                                                    ; top-1
```

i.e. arguments are addressed **relative to the top of the stack**, not absolutely. This
matches the usage string `Usage : RainSetTailColour(red,green,blue,alpha)` at
`0x005cf588`.
