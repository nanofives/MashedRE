## Correction (2026-10-09)

The 2026-05-12 text of this note (and `re/analysis/bucket_util_0040e4b0_0042f790/0x00414180.md`)
followed the decomp and was wrong on three points:
1. `FUN_004a2c48` is `_ftol2`. It is not a "time/counter source": each call converts the current ST0
   to an int (once for `DAT_0089a360`, once for the random draw), so the two calls take different
   inputs (U-8939, U-6010 resolved).
2. `FUN_00472650` returns its result in ST0, and that value is what the second `_ftol2` stores.
3. The `DAT_007f0fd0` branch at `0x004141da` is missing from the decomp.
