## 2. MEASURED — what was wrong in the port, by listing

### 2.1 `FUN_00443300` was already verbatim; the stub entry was stale

The decompilation matches `CatmullRom` term for term, including the index wrap and the
parameter clamp. Only the ledger line claimed it was stubbed.

### 2.2 `FUN_00443dc0`: two deviations, one missing tail

- **Phase 2 index continuity** (`0x00443e86..0x00443eb4`): the original keeps the stored
  index when the nearest point jumps by more than one, except the wrap step `1-count`, and
  only when the stored index is inside the bank. The reset value is **1000** (writes at
  `0x00414015` in `FUN_00413fe0` and `0x00414040` in `FUN_00414030`), so the next call
  after a reset takes the true nearest point. The port had replaced this with a
  "far from the stored point" heuristic. That heuristic is gone. `Ai_ResetRace` (ports
  `FUN_00413fe0`) runs at race load, and `Ai_ResetVehicleIndex` (ports `FUN_00414030`)
  runs whenever the standalone relocates a car.
- **Phase 8, the wall-march** (`0x004446a4..0x00444a5e`), ported verbatim in place of the
  host line-of-sight approximation. It marches the centre line own→target and then an
  offset line whose start is `(own.x - 0.25*dz/len, own.z - 0.25*dx/len)`
  (`0x00444875..0x0044489d`). Each sample probes the `.AI` tile grid:
  `rz = ftol(z*4 ±0.5) - 0x10`, `rx = ftol(x*4 ±0.5) - 0x10`,
  `s = word[0x007f1a9c + (((rz+0x200)>>3)*0x80 + ((rx+0x200)>>3))*2]`, blocked iff
  `0 < s < 0x200` and `byte[0x007f9a9c + ((rx&7) + s*8)*8 + (rz&7)]` is 0 or 3
  (`0x00444754..0x00444807`). A blocked line steps the target back by 2 (0/1 → 0, done);
  `FUN_00416230(v, idx==0)` writes `0x0089a500 + v*0x74` on each pass (`0x00444a2c`); when
  any pass was blocked, one more step back is taken at the end (`0x00444a40..0x00444a5b`).

### 2.3 `FUN_00443440`, the curvature walk, was not in the port at all

`FUN_00416250` calls `FUN_00443440(spline, pos, 10.0, &curv, 0)` at `0x004162b0`, discards
its return (`FSTP ST0`, `0x004162b5`) and folds `curv` to [0,180] (`0x004162be..0x004162d5`).
The function repeats the nearest/ternary search, takes the tangent heading `h0` at the
closest parameter (`FUN_004233e0`: `180 + atan(a/b)*57.2958`, +180 when b > 0, 90/270
when b == 0), walks the spline in +0.1 steps accumulating **squared** chord lengths to
`dist`, takes the tangent heading `h2` there, and stores `h0 - h2` wrapped to [0,360).
Ported as `SplineCurvature` + `Heading004233e0`.

### 2.4 `FUN_00416250`: the bands were right, four of their inputs were not

Stack frame after the prologue: `[+0x10]` mode, `[+0x14]` err, `[+0x18]` curvature,
`[+0x1c]` `FUN_0046d6d0` = record `+0x9e4`, `[+0x20]` `FUN_0046d6a0` = record `+0xb0c`,
`[+0x24]` `FUN_0040e350`. The x87 stack through the bands was traced by hand from
`0x004165a5`.

| Item | Original (listing) | Port before |
|---|---|---|
| fresh-steer magnitude | `err * [+0x9e4] * 0.0030034`, then `* (curv*0.05)` when mode == 0 and curv > 20 (`0x00416648..0x00416679`) | `err * |vel| * k`, then `* 0.05` when `rate1 <= 20`, with `rate1 = 0`, so always `* 0.05` |
| mirror magnitude (err > 180) | `(360 - err) * …` (`0x0041675c..0x00416768`) | `err * …`, which saturates at 255 |
| brake rule at `0x00416818` | compares the x87 **history value** X with 20 (X = the previous err if it was lower, or `360 - hist` on the other side) and `[+0x9e4] > 2000` | compared err, with `rate1 = 0`, so never fired |
| speed-spike rule | on `[+0xb0c]` (`0x004167d5..0x0041680e`) | on `|vel|` |
| `DAT_0089a368 == 1` accel × 0.4 (`0x004169e0`) | present | absent |
| `FUN_004a2c48` | **truncates** (FISTP + residual-sign ADC correction at `0x004a2c48..`; confirmed by `0x40 * 0.4` stored as 25 in the original) | modelled as round-to-nearest |
| heading in `FUN_00415e20` | body **forward** vector via `FUN_0046d510` (transforms `DAT_00614708 = (0,0,1)` by the car matrix, returns `+0x9d4`); every wrap is `<= 0 → +360` | velocity vector, `< 0` wraps |

### 2.5 The clock was never advanced standalone

`DAT_007f1008 = ESI` at `0x0040fc63` (the same ESI is pushed to `FUN_00425a40` at
`0x0040fc6b`, the physics budget), and `DAT_007f0ff4 += ESI` / `DAT_007f0ff8 += ESI` at
`0x0040fe4f..0x0040fe5e` (skipped in race sub-state 7, `0x0040fe46`). Nothing in
`mashed_re.exe` wrote them. With the clock frozen at 0, `el = clock - start` was always
0, so `FUN_00416250` never issued a fresh steer: the only non-zero steer bytes came from
the full-lock bands. **This, not the lookahead, is the main cause of the 2-3 distinct
steer values measured on 2026-09-14.** `Ai::Ai_AdvanceClock(dt*3000)` now runs before the
tick (50 per 60 Hz frame, as measured).

### 2.6 The difficulty tables were zero standalone

`FUN_004177b0` rolls against two int tables at `0x005f30a0` / `0x005f3180` (row
`__ftol(DAT_0089a360)`, 5 bands). The standalone pad held zeros, and with the old
`return lo` random stand-in that set `DAT_0089a368 = 1` on every band change. The tables
are harvested from the original's `.data` into `kDiffProb1/2`, `DAT_0089a360 = 2.5`
(measured) at race load.

## 3. PORTED — FUN_00415220 and the opponents on the ctrl bytes

- **`FUN_00415220` → `AiFireDecision`** (`0x00415220..0x0041582a`, jump table `0x0041582c`,
  types 7..19). cdecl `(spline, &target, &cand, v, curvInt)`; arg 5 is `__ftol(curv)`
  pushed at `0x00416523`; `FUN_0046d6d0` overwrites arg 4's slot with the speed
  (`0x00415244`). Every path returns 0 (`XOR EAX,EAX` before each `RET`), so the caller's
  mode-8 commit at `0x0041655b` is dead in the original too. Per-vehicle state at
  `0x0089a51c/520/524/528` (stride 0x74); it writes `ctrl[7] = 1`. Called from
  `ControlStep` under sub-state 6 and `FUN_00443080() == 0` (`0x0041649b` / `0x004164a8`),
  with the held-power-up reset at `0x0041651f → 0x00416565`.
- **`FUN_00472650`**: the law `(hi-lo)*(u & 0x7fffffff)*2^-31 + lo` is verbatim
  (`_DAT_005cd314 = 0x30000000`); `u` comes from `FUN_00534870`, RenderWare's lagged
  generator, whose ring the standalone does not have. A 32-bit LCG stands in.
- **Opponents drive from the ctrl bytes.** The Option B motion model at the old
  `TrackRenderer.cpp:2831-2960` is gone from the default build. Each opponent is stepped
  through `VehiclePhysics_StepCar(v, …)` with `raw_steer = 1` and `input[] = its ctrl block`,
  the bytes A4 `FUN_00470670` reads (`0x00470732` / `0x00470754`) and A6a reads (`[4]`/`[5]`).
  Option B survives as `TrackRenderer::AiOptionBStep`, reached **only** on the D2 revert
  `MASHED_REAL_PHYSICS=0`, where there is no chain to feed.
- **`MASHED_AI_TICK` is deleted**, not inverted. `MASHED_AI_PUREPURSUIT`,
  `MASHED_AI_STEERFLIP` and `MASHED_AI_NAV` went with the pure-pursuit shim inside the
  old `ControlStep`. `MASHED_GATE_RIBBON_AI` stays: it is still the documented A/B revert
  at the `Ai_BridgeLoad` call.
- Host changes: `ai_target_enable` now returns 0 (measured, §1.1; the old 1 skipped the
  fire block, stepped the player through the AI tick and forced `DAT_0089a368 = 2` every
  frame). New host members `own_fwd_xz`, `veh_f32` (reads the ported physics record),
  `held_powerup` (reads `PowerupSystem`).
- Standalone glue kept, recorded here because the original does something else: a car
  whose gate progress stalls for 2.5 s is relocated two gates ahead (stand-in for the
  unported `FUN_00470c70` respawn branch), and an off-mesh step uses the player's ring
  probe. Both now reset the car's lookahead index and body basis.
