# AudioPoolBlockAlloc — bitmap pool block allocator

> **Correction 2026-10-12 (negctl re-earn, re-ported from the bytes of MASHED.exe.unpatched; supersedes the text below where they disagree).** The bitmap scan is bounded by a per-block countdown seeded from param_1[1] (0x005ae828, kept in the param slot [esp+0x18]): a 0xff byte subtracts 8 (0x005ae90d), each set bit subtracts 1 (0x005ae85c), and countdown == 0 ends the current byte (0x005ae848; `test`/`jbe` is a zero test, so the unsigned count can wrap after a 0xff byte). An address of 0 keeps scanning (0x005ae88c). A new block is HEAD-inserted: new[1] = sentinel, new[0] = old head, old_head[1] = new, sentinel[0] = new (0x005ae8e3..0x005ae8f3).

## Algorithm

```
Scan existing blocks in circular list at param_1[4]:
    for each block:
        scan bitmap bytes (param_1[2] bytes at block+8):
            if byte == 0xff: skip
            else: find first clear bit via 0x80>>i loop
                  set bit; compute & return aligned address
If no free slot:
    FUN_005aea00(param_1[1]*param_1[0] + param_1[3] + 8 + param_1[2], param_2) → new block
    zero bitmap; mark bit0; insert into circular list; set initial byte = 0x80
    compute & return address
```

## Address formula

`(block + param_1[2] + param_1[3] + 7) & ~(param_1[3]-1) + bit_index * param_1[0]`

where `bit_index = byte_idx * 8 + bit_pos`.

Complement: `FUN_005ae920` (free — clears a bit in the bitmap). Both operate on `DAT_009146c0` for the node-list pool.
