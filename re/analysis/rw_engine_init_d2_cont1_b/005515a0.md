### Two details the decompiler output does not make obvious

- **`MOV [0x009124f8],EAX` at `0x005515ec` stores call 2's return, not call 3's.** It sits
  *between* the argument pushes for call 3 (`0x005515d8..0x005515e7`) and the `CALL` at
  `0x005515f1`. The intervening `PUSH`es do not touch EAX, so the value stored is still
  `FUN_004e80c0`'s result. Reading the store as belonging to the nearer call would invert
  which registration the global tracks.
- **`ADD ESP,0x24` at `0x005515f6` is a SINGLE combined cleanup for TWO `__cdecl` calls.**
  Call 2 pushes 5 dwords and call 3 pushes 4; `0x24` = 36 = 9 dwords covers both at once.
  Only call 1 gets its own `ADD ESP,0x10` (`0x005515b6`). A port that cleaned up after each
  call separately would unbalance the stack.
