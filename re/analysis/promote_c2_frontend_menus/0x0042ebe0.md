## Correction 2026-10-12 (reearn/fstate, from the bytes)

The field table above is wrong; it came from reading Ghidra's dword-indexed `piVar2[k]` as bytes.
From the disassembly:
- The loop (base 0x7f0a48, 0x0042ed53 add eax,0x1e0, 0x0042ed58 cmp eax,0x7f0c28 ; jl) runs
  exactly ONCE: 0x7f0a48 + 0x1e0 == 0x7f0c28.
- p == 10 checks [base-4] (0x0042ebf5) and [base+0x2c, 0x5c, ... 0x1ac] (0x0042ec18..0x0042ec7a):
  column 0x7f0a44, rows 0..9, stride 0x30. p == 11: [base] (0x0042ebff) and [base+0x30 ... 0x1b0]
  (0x0042ec8a..0x0042ecd4): column 0x7f0a48 rows 0..9. p == 12: [base+0xc] (0x0042ec08) and
  [base+0x3c ... 0x1bc] (0x0042ece1..0x0042ed49): column 0x7f0a54 rows 0..9.
- ANY of those ten cells == 0 sets the flag (0x0042ece8 mov ecx,1) and leaves the loop. The
  9-field checks do set it; the old port's 9-field loops never did.
- Return (0x0042eced..0x0042ed02): `[0x7f0a44 + p*0x30] != 0 && flag == 0`, as a full dword
  0/1 (xor eax,eax ; sete al). The enable flag stride is 0x30, not 0xc.
