# Arctic ("Timgidski") sea renders at road height — root cause (2026-09-29)

Investigation session on `race/first-frame-parity`. No build, no edit under `mashedmod/src`
(another child session owns the build tree). The standalone was run only from a frozen copy.

**Verdict:** the original runs a **per-track post-load hook** for Arctic that translates the
`sea.dff` clump to **Y = −4.1** and lays **25 tiles on a 5×5 grid at 60 m spacing anchored at
(−150, −4.1, −150)**. Our port pushes a single **identity** instance, so one 60×60 m sea patch
sits at **Y ≈ 0**, which is the road surface (GRAPH.BSP median Y under the start grid = 0.250).
Fix = reproduce the hook's placement in the `Clump_Filename` prop loop.

## 1. MEASURED — the track is **Arctic**

"Timgidski" is the in-game display name of the area our source calls `Arctic`
(`original/TOASTART/TRACKS/Arctic.piz`, `Course_Id(0)`, `kAreas[0]`, `MASHED_TRACK_SEL=0`,
engine track index 3, `MASHED_TRACK_VIEW=Arctic`). Three independent witnesses:

1. **Message table.** `Font36.piz :: ENGLISH.DAT` (677 ids) carries the 13 area names in one
   run: `Angel Peak, Kharga Temple, Neustein, `**`Timgidski`**`, Ventura Blvd, Keister Bay,
   Polar Wharf, Tierra Piedra, Koko Bay, Silver Creek, Redpool Tip, Nukov, Hattan City`.
   Position 3 (0-based) = Timgidski.
2. **Behavioural, already on record.** Bronze Cup 1 row → loaded `.piz`, confirmed 2026-08-31 by
   `CreateFileA/W` observation under an unlocked save copy
   (`verify/arctic_ref/FINDINGS.md`): `0→TRAINING, 1→EGYPT, 2→NEUSTEIN, `**`3→ARCTIC`**.
   Row labels are msgid `0x49 + row` (measured on the string-draw entry `0x00427e00`), so row 3
   is msgid `0x4c` = the 4th name above = Timgidski.
3. **Track-preview texture names.** `exe_main.cpp:6924` (slot table `0x005f79d8`, `SFX.piz ::
   TRACKIMAGES.TXD`): position 3 of the 12 pairs is literally `Timgidski1`/`Timgidski2`, and the
   same ordinal in the engine track table is Arctic.

Corroborating: the per-track hook table at `0x005f33f8` (§4) stores the literal ASCII
`"arctic"` at `0x005f3488` with `Course_Id = 0` at `0x005f3498` — the same Course_Id
`Arctic/COURSE.LUA` declares (`Course_Id(0)`) and the same one `kAreas[0]` carries.

**No other area matches.** Arctic is the only track in the game whose water clump is *not*
`Clump_Exclude_From_World`, which is why it is the only one where this defect can show.

## 4. MEASURED — what the ORIGINAL does (RVA-cited)

### 4.1 The loader sets no matrix

`FUN_00479330` (`Course::CreateFromDescription`, decompiled this session) loads every clump with
a non-empty filename into `course + 0x10110 + idx*4`, sets the loaded flag at
`course + 0x103b0 + idx*4`, zeroes `course + 0x104b0 + idx*4`, then walks the 0x40 slots and
calls `0x004e4450(world, clump)` only when the exclude flag `desc[0x35 + idx]` is 0, plus
`0x00474fd0` (first atomic) unconditionally into `clump_slot[0x48]`. **No frame transform
anywhere in that function.** So at end of load the sea clump's frame is the DFF's identity.

### 4.2 The per-track hook table

`0x005f33f8` — array of records, **stride 0x48**, count at `[0x005f37a0]`:

```
+0x00  char  name[0x10]      "training" "superg" "arctic" "rouabout" "sands" "warzone" "forest" "egypt" ...
+0x10  u32   Course_Id       30         25       0        2          11      33        34      ...   (== kAreas)
+0x14  void* slot[13]
```

- Selector `FUN_0041e870` (called at `0x00426eaf`): `cmp [eax+0x10], edx` / `add eax, 0x48`
  (`0x0041e890`, `0x0041e89a`), stores the matching record into **`DAT_0063d7e4`**
  (`0x0041e895`).
- Thunk `0x0041e8b0`: `mov ecx,[0x0063d7e4]` / `jmp dword ptr [ecx+0x14]` — i.e. **slot 0**.
  Invoked at `0x0042709f` after `push 0x646e58` (`0x0042709a`), gated on `0x0041e9d0`.
  `0x00646e58` is the **course object** — the same global `FUN_00426ab0` passes as `param_1` to
  `FUN_00426700`, which indexes `param_1 + 0x10110 + idx*4`.
- **Arctic record**: name `"arctic"` at `0x005f3488`, `Course_Id = 0` at `0x005f3498`,
  **slot 0 at `0x005f349c` = `0x00448940`**.

### 4.3 `FUN_00448940` — the Arctic hook (entry at `0x00448940`: `sub esp,0x24; push ebx/ebp/esi/edi`)

`esi` = the course object. Reached only through the table above (no direct call site exists in
`.text`).

```
0x0044899d  mov ecx, [esi + 0x10118]        ; course clump[2]  == Clump_Filename(2,"sea.dff")
0x004489a3  mov edx, [ecx + 4]              ; RwObject.parent == the clump's RwFrame
0x004489b3  mov [esp+0x48], 0               ; translation.x = 0.0
0x004489bb  mov [esp+0x4c], 0xc0833333      ; translation.y = -4.1      <<< THE WATER LEVEL
0x004489c3  mov [esp+0x50], 0               ; translation.z = 0.0
0x004489cb  mov [0x008963e0], eax           ; sea clump stored as TILE 0
...
0x00448a40  mov ecx, [0x008963e0]           ; clone loop
0x00448a47  call 0x004e6ab0                 ; RpClumpClone(seaClump)
0x00448a4c  mov [edi], eax                  ; edi: 0x008963e4 .. 0x00896440
0x00448a5d  cmp edi, 0x00896444             ; -> 0x60/4 = 24 clones  (+ base = 25 tiles)
0x00448a65  mov [esp+0x10], 0xc3160000      ; X start   = -150.0      (outer loop)
0x00448a6f  mov ebp, 5                      ; outer count 5
0x00448a80  mov [esp+0x18], 0xc3160000      ; Z start   = -150.0      (reset per outer row)
0x00448a88  mov ebx, 5                      ; inner count 5
0x00448a90  mov ecx, [edi*4 + 0x008963e0]   ; tile clump
0x00448a97  mov edx, [ecx + 4]              ; its frame
0x00448a9a  push 0                          ; combine op 0 = rwCOMBINEREPLACE
0x00448a9c  lea eax, [esp+0x14]             ; -> the vector at (x, y, z) = (+0x10, +0x14, +0x18)
0x00448aa2  call 0x004c1340                 ; RwFrameTranslate(frame, &v, 0)
0x00448aab  fadd dword ptr [0x005cc728]     ; Z += step        ([0x005cc728] = 60.0)
0x00448ac1  fadd dword ptr [0x005cc728]     ; X += step
```

The Y slot `[esp+0x14]` is written **once**, with `-4.1`, and is never touched by either loop.
So the 25 tiles land at

```
X, Z ∈ { -150, -90, -30, +30, +90 }        Y = -4.1 for all 25
```

i.e. a **330 × 330 m sheet** (each 60 × 60 tile spans ±30 about its anchor) covering
X, Z ∈ [−180, +150], against a track bbox of X ∈ [−62.3, 32.3], Z ∈ [−73.0, 57.2].

**`-4.1` and the `-150.0` pair are the only such immediates in the whole image** — a raw byte
scan of `MASHED.exe.unpatched` finds `c0833333` exactly once (file 0x489bf = VA `0x004489bf`)
and `c3160000` three times, two of them at VA `0x00448a69` / `0x00448a84` (this loop) and one
stored constant at `0x005e6190`. The triple `(-150, -4.1, -150)` appears nowhere as data.

## 5b. MEASURED — the sea is placed ONCE, and nothing moves it afterwards (closes U1)

Added 2026-09-29, second pass. This is the check that decides whether "25 static instances" is
the whole placement model or only its first frame.

**Whole-`.text` sweep for the tile array.** `re/tools/findconst.py 0x8963e0 0x8963e4 0x896444`
returns clean `mov`/`cmp` decodes at exactly **three** functions (the remaining raw matches —
`adc eax,0x8963e0` @ `0x00448a25`, `or eax,0x8963e0` @ `0x00448a41`, `inc [esp-0x77]` @
`0x00448a5f` — are mid-instruction artifacts of the byte scan; linear disassembly from
`FUN_00448940`'s entry shows `mov edx,[0x8963e0]`, `mov ecx,[0x8963e0]`, `cmp edi,0x896444`
there. See memory `capstone-sweep-stops-at-bad-byte`):

| Arctic slot | function | what it does with the 25 tiles |
|---|---|---|
| **0** `0x005f349c` | `FUN_00448940` | **places** them (§4.3) and clones 24 |
| **2** `0x005f34a4` | `0x00449030` | **renders** them: `mov esi,0x8963e0` @ `0x0044903b`, loop `0x00449040`–`0x00449054` calling `0x004e6680(tile)` per entry up to `0x00896444`, then eight two-argument calls through `RwGlobals+0x20`; `ret` at `0x004490c5` |
| **5** `0x005f34b0` | `0x004490d0` | **destroys the clones**: `mov esi,0x8963e4` @ `0x00449119`, loop `0x00449120`–`0x00449134` calling `0x004e6e00(tile)`. It starts at `0x8963e4`, i.e. it frees the **24 clones and not the base** — independent corroboration of the 1-base+24-clones reading, since the base belongs to the course loader (`FUN_00478cf0`). |

**No `0x004c1340` (frame translate) call anywhere in slot 2 or slot 5.** Likewise
`re/tools/findoffset.py 0x10118` shows only `0x0044899d` and `0x004489ac` in the Arctic band,
both inside `FUN_00448940`.

**The per-frame Arctic hook does not touch the sea.** Slot 1 = `0x00448ef0`, reached through
thunk `0x0041e8c0` (`jmp [rec+0x18]`) called at `0x00426ae3` from the per-frame `FUN_00426ab0`.
Its body calls `FUN_00448cb0` / `FUN_00448e20` / `FUN_00448dc0` and then a sinusoidal bob:
`_DAT_00683250 += _DAT_005cc9c0`, `fsin`, `FUN_00488390((&DAT_008962e0)[DAT_00683248], …)`.
That is **`DAT_008962e0`**, a different array (the one `FUN_00448940` fills at `0x00448b68` and
slot 5 frees first) — **not** the sea tiles at `DAT_008963e0`. One hex digit apart; worth saying
out loud.

**RW identities confirmed** (decompiled, `Mashed_pool0`, read-only), so the patch comment's
claims are not assumed:

- `0x004c1340(frame, v, op)` → `FUN_004c51a0(frame + 0x10, v, op)`, and `0x004c51a0` already
  carries `RwMatrixTranslate` in Ghidra. `frame + 0x10` is the **modelling matrix** — the exact
  offset §4.4 read live. It then dirties the frame (`|= 0xc`) and links it into the dirty list
  at `RwGlobals(DAT_007d3ff8) + 0xbc`. So it is **`RwFrameTranslate`**.
- `0x004e6ab0` allocates via `FUN_004e6d80` and sets the new clump's `+4` from
  `FUN_004c0870(*(clump+4))` — a **clump clone that clones the frame**, which also re-confirms
  `clump+4 == the RwFrame`.
- `0x004e6e00` is already named **`RpClumpDestroy`** in Ghidra.
- `0x004e6680` walks the clump's atomic list at `+8`, tests flag bit 4, and calls each atomic's
  callback `(*(code*)puVar2[2])(atomic)` — **`RpClumpRender`**.

**Conclusion: the Arctic sea is positioned exactly once, at load, by `FUN_00448940`.** A static
25-instance list is therefore the complete placement model, and §8's fix is not a first-frame
approximation.

## 6. REFUTED

- **"Render state — depth test/bias/draw order."** The sea is opaque geometry occluding the road
  from a camera 4.5 m above it; the cars still draw over it. The world-space placement is wrong
  (§4.4 vs §5), so no depth/order hypothesis is needed and none is supported.
- **"The `.UVA` / UV animation moves it."** `SEA.UVA` is a texture-coordinate scroll only
  (`bmp_Sea_M`, dv/dt = 0.1818 u/s), already wired at `TrackRenderer.cpp:5379-5390`. It cannot
  change a vertex or frame position.
- **"A Lua command places it."** The full 68-entry binding table has no such command (§3).
- **"The course loader places it."** `FUN_00479330` sets no frame matrix for clumps (§4.1).
- **"The clump-anim tick places it."** `FUN_00426700` (called per frame from `FUN_00426ab0`,
  itself called from `FUN_0040fc00`) samples an animation and calls
  `FUN_004756e0` → `FUN_004c1480(frame, matrix, 0)` — but only for the records at
  `DAT_00644158 + 0x70` (count at `+0xd0`), which come from `SetClumpAnim` / `SetCopter`.
  Arctic binds no anim to clump 2.
- **"Water level is −3.618 (the wave splines)."** Close but **not** the number the engine uses:
  the splines are at −3.618, the sea sheet is at **−4.1** (§4.3, §4.4). Cite −4.1.
