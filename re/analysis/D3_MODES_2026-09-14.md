## 3. OPEN — two blind spots, neither closed

A GREEN over a branch that never ran is worth nothing, so both are stated rather than
folded into the verdict.

### 3.1 The finish-order APPEND branch never fired

`ord.appends == 0` and `ord.resets == 0` in **all five runs**, including both `--poke-lap`
runs. So all 2847-3963 agreeing `UpdateFinishOrder` calls per run took the no-append path,
and the append gate — the `kFinishThreshold = 3.0` metric compare and the `-1.0` slot
sentinel fill (`_DAT_005cc31c` / `_DAT_005cc33c`) — is **untested**.

`--poke-lap 0:3` was expected to drive the metric past the threshold and did not. Not
diagnosed; no mechanism is asserted here.

Next command — verify the poke actually moves the metric before trusting any append result:

```
py -3.12 re/frida/scenario_launch.py --track 0 --mode 10 --cars 4 --car 0 --rule 0 \
    --oracle --poke-ctrl-slots --poke-lap 0:4 --poke-delay 15 --hold 90
```

then read `ord.lastOrder` and `samp` in `log/rules_oracle_rule0.json` across the poke, and
if the metric does not cross 3.0, instrument `DAT_0089a880[car]` directly rather than
poking the lap row.

### 3.2 Rule coverage is 3 of 11

Rules 0, 1 and 2 are measured. `DAT_007f0fd0` ranges 0..10. Rule 5 (collect-all) and rule 10
(countdown) have their own pre-blocks in `SegmentCheck` and their own seeds
(`Rule10Seed` from FUN_004046a0, `Rule10Tick` from FUN_004039f0) and are untouched here.
Rule 5 additionally has the documented `rule_engine_race_on_` fallback
(`TrackRenderer.cpp:3481-3486`) when a track carries no `KTC_NewCopter` collectibles.

Next command: the same oracle invocation with `--rule 5 --poke-collect <total>:<done>` and
with `--rule 10 --rule10-timer <seconds>`, which exist for exactly these two pre-blocks.
