# U-9138 — flip `Vehicle::Rw_TransformPoints` to the vectors form: plan, pass rule, evidence

Session 2026-09-28. Branch `race/first-frame-parity`. Written **before** any source edit,
so the pass rule cannot be chosen after seeing the numbers.

## 1. What is being fixed

`mashedmod/src/mashed_re/Vehicle/ForceIntegratorStubs.cpp:39` binds `Rw_TransformPoints`
to `Math::RwV3dTransformPointsCPU`, which adds the matrix translation row `m[12..14]`.

`re/analysis/D3_CONTACT_2026-09-27.md` §2.2 (commits f39747af, 61b06778) MEASURED that
the device slot the original dispatches here — `+0x14`, reached by `FUN_004c3df0`
(`MOV EAX,[0x7d3ff8]` `0x004c3e02`; `MOV ECX,[0x7d3ffc]` `0x004c3e08`;
`CALL [ECX+EAX+0x14]` `0x004c3e10`) — **ignores** that row, while slot `+0xc`
(`FUN_004c3d90`) adds it. Four Frida diffs decide it:

| hook | original | reimpl side | result |
|---|---|---|---|
| `rw_v3d_transform_points_argfix` | `0x004c3df0` | `RwV3dTransformPoints` (ported thunk) | GREEN 10/10 |
| `rw_v3d_transform_points_cpu` | `0x004c3df0` | `RwV3dTransformPointsCPU_C` | **RED 4/10** — exactly the 4 vectors with a nonzero pos row |
| `rw_device_dispatch_0c_points` | `0x004c3d90` | `RwV3dTransformPointsCPU_C` | 9/10, 10th off by 1 ULP |
| `rw_v3d_transform_vectors_cpu` | `0x004c3df0` | `RwV3dTransformVectorsCPU_C` | GREEN 10/10 |

`Collision::Rw_TransformPoints` (`ContactStubs.cpp:70`) was flipped to
`RwV3dTransformVectorsCPU` on 2026-09-27. The `Vehicle::` copy was deliberately left
alone then, because the D2 physics gate had been measured against the current
behaviour. U-9138 is that deferral. The user approved the flip on 2026-09-28.

## 3. Why a numeric re-check is still required even though the defect is latent

U-9138 records the flip as latent: every live caller today passes a zero-pos matrix
(`VehicleControl.cpp:186` passes a pure yaw world-ROTATION built at
`VehicleControl.cpp:178-185`; `ForceIntegrator.cpp:70` memsets `m` before
`RwMatrixRotate` mode 0, which writes `m[12..14]=0` at `RwMatrixRotateInner.cpp:150`;
`Integrate2.cpp:288` declares `float m40[16]` uninitialised and relies on that same
mode-0 write for its pos row). If that
argument is complete the flip changes nothing at all. The re-check exists to **test**
that argument against the physics the closed D2 gate was measured on, not to assume it.

## 5. Pass rule — fixed before the measurement

**PASS** iff every metric above, post-fix, is identical to the PRE-FIX control within
that metric's run-to-run noise, where "run-to-run noise" is bounded by the spread
already on record for this recipe between the two September clean runs of the same
build family (`verify/a8_order_20260913/a4first` vs `verify/d2_close_20260914/cleanenv`:
slip 2000-2600 moved 0.2630 -> 0.2668, i.e. 1.4%; slip 1500-2000 0.1916 -> 0.1916;
av.y 1.583 -> 1.589). Concretely:

- slip vs fwd, either band: |post - pre| <= 0.005 absolute
- av.y, either band: |post - pre| <= 0.02
- driving-median speed: within 2%
- max speed: within 2%
- momentum eff-dt port/orig, each band: within 0.03

The expected result, given §3, is **bit-identical logs**. If the metrics move at all
beyond the bounds above, **U-9138 is NOT closed**; the delta is reported and the
session stops there rather than re-arguing the bound after the fact.
