## Purpose (C3 prose, added 2026-10-01 retrofit lane)

**Append one pickup to the 25-entry pickup pool and return its index, or return
-1 when the spawn is rejected.** Three rejections, in the original's own order:
the pool is full (`0x00458e0c` `cmp edx,0x19` + `jl`, a SIGNED test); the position
coincides with an entry already in the pool (`d^2 < _DAT_005cc558` against the
LIVE position at `+0x2c`, walking DOWN from `count-1`); the type is `0x15`
(BLANK). On the rank-2 arm a BLANK is not rejected but REPLACED by a randomly
chosen type and flagged at `+0x28`.

Two corrections to the mechanical pass below, both from the disassembly:

1. `FUN_0042fe30` is NOT a "game-mode getter". It is `RaceEndFlagIfEndMode`,
   **C4**, ported at `mashedmod/src/mashed_re/Frontend/MenuRaceEnd.cpp`: it
   returns 1 when the race sub-mode is `0xb` and otherwise `DAT_0067ea74`. The
   only read of that value here is `cmp ebp,2` at `0x00458e7b`, so every value
   except 2 takes the identical path. Live measurement on the race path reads 1
   (`verify/pickups_fix_20261001/RESULT_STAGE1.md` P1). This resolves U-8325.
2. The dedupe sum order is the x87 stack's, not the decompiler's. Ghidra prints
   `dz*dz + dx*dx + dy*dy`; tracing the eight ops at `0x00458e44..0x00458e52`
   gives `(dy*dy + dx*dx) + dz*dz`, which is what the port computes. No ordering
   can change a verdict against 1e-3, but the port says what the instructions say.

## Mechanical description
- `int FUN_00458e00(float *param_1, int param_2)` — body 0x00458e00..0x00458f11. **Spawn a pickup-pool entry.** `param_1` = world position xyz; `param_2` = requested type id. Returns the new slot index, or `-1` on rejection.
- This function defines the canonical **pool record layout** (base `0x68b198`, stride `0x50`, max 25 slots 0..0x18). `iVar6 = count*0x50` (byte offset), `iVar5 = count*0x14` (dword offset).
- `iVar2 = FUN_0042fe30()` — read current game mode.
- **Capacity gate**: if `DAT_0068b9a8 > 0x18` (>24) → return -1.
- **Proximity dedup**: if count>0, walk existing entries; reject (`return -1`) if any existing live position (`+0x2c..0x34`, the `pfVar4[-0x15/-0x14/-0x13]` window) is within `_DAT_005cc558` squared distance of `param_1` — no two pickups too close.
- Write new record at index `count`:
  - `+0x28` (DAT_0068b1c0) = 0 (flag); `+0x24` (DAT_0068b1bc) = `param_2` (type id).
  - **Mode-2 branch**: if `iVar2 == 2`: require `param_2 == 0x15` else return -1; then `+0x24 = FUN_00458d00()` (random type) and `+0x28 = 1`.
  - Else if `param_2 == 0x15` → return -1 (type 0x15 only legal in mode 2).
  - `FUN_00458dd0(&DAT_0068b198 + iVar5)` — re-skin visual for the chosen type.
  - `FUN_004c15c0(*(render_obj +4))` — RW reset/show of the entry visual.
  - Position copies: `+0x2c/30/34` (origin, DAT_0068b1c4/c8/cc) = `param_1[0..2]`; `+0x38/3c` (live, DAT_0068b1d0/d4) = `param_1[0..1]`; `+0x40` (DAT_0068b1d8) = `param_1[2]`.
  - `DAT_0068b9a8++` (bump count); `+0x20` (DAT_0068b1b8) = 1 (state=active); `+0x18` (DAT_0068b1b0) = `0x42f00000` (=120.0f TTL); `+0x1c` (DAT_0068b1b4) = 0 (timer).
  - Returns the pre-increment count (the assigned slot index).
