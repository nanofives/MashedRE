## 1. The stated hypothesis was REFUTED

The kickoff hypothesis was: *"the original's MISSILE FIRE consults the aim record
at `0x006885d0 + slot*0x2c` and the port consults none."*

It does consult it, and the port already matches. `FUN_00455150` (the MISSILE
FIRE, read with `decomp_pc.py --create`) refuses on exactly one condition:

```
0x00455163   if (*(int *)(&DAT_006885d8 + slot*0x2c) < 1) return;
```

`&DAT_006885d8` is that pool record + `0x08`, which `re/tools/pu_diff.py` already
maps to the port's `ammo` (`FIELDS[11]`). `FUN_00455060` (ARM) writes `1` there —
`IMUL ESI,ESI,0x2c` `0x00455073`, `MOV EAX,1` `0x00455076`,
`MOV [ESI+0x6885d8],EAX` `0x00455081` — and the port's `Missile_Arm` /
`Missile_Fire` reproduce both. So the refusal the hypothesis predicted was already ported, and the capture confirms it
was not the one taken: **the original never called FIRE at all.**

## 3. The gate, disassembled

`re/tools/findconst.py 0x0068d1f0` — **three** references in `.text`, no more:

```
0x0045ba0b  mov dword ptr [ecx*4 + 0x68d1f0], eax     ; the setter
0x0045bc6e  mov eax, dword ptr [ecx*4 + 0x68d1f0]     ; the dispatcher's read
0x0045bc88  mov dword ptr [ecx*4 + 0x68d1f0], 3       ; the dispatcher's latch
```

The dispatcher `FUN_0045bba0`, from the pinned anchor. `EDI = slot + 0x90`, so
`[EDI+0x18]` is the active ENTRY (`+0xa8`) and `[EDI+0x1c]` the armed handle
(`+0xac`):

```
0x0045bc2b  cmp eax, 6                       ; race sub-state
0x0045bc61  jne 0x45bdc1                     ; != 6 -> whole per-slot pass skipped
0x0045bc67  mov ecx, [esp+0x10]              ; ECX = slot index
0x0045bc6b  mov eax, [ecx*4 + 0x68d1f0]
0x0045bc72  cmp eax, 4
0x0045bc75  je  0x45bdc1                     ; 4 -> skipped
0x0045bc7b  cmp eax, 2
0x0045bc7e  jne 0x45bca2
0x0045bc80  mov eax, [edi+0x18]              ; the +0xa8 ENTRY, NOT +0xac
0x0045bc83  test eax, eax
0x0045bc85  mov dword ptr [ecx*4+0x68d1f0], 3  ; unconditional in this arm
0x0045bc90  je  0x45bdc1                      ; entry == 0 -> out, no deactivate
0x0045bc98  call 0x45bac0                     ; deactivate; RETURN ADDRESS 0x45bc9d
0x0045bc9d  jmp 0x45bdc1
0x0045bca2  cmp eax, 3
0x0045bca5  je  0x45bdc1                     ; 3 -> skipped
0x0045bcab  mov eax, [edi+0x1c]              ; ONLY NOW the armed test
```

Two details that a careless port would get wrong, both taken from the bytes:

1. The `== 2` arm guards its `FUN_0045bac0` on the **`+0xa8` entry**, not the
   `+0xac` armed handle the rest of the function keys on.
2. The store of `3` at `0x0045bc85` is **unconditional** within that arm — it
   happens whether or not the deactivate runs.

The RA `0x45bc9d` is not a deduction: four captures record it in their own
`deact_ra` column (`s2` slot 0 and slot 1, `s1` slot 1, `m1` slot 1, `m2` slot 2).

## 5. The port

`mashedmod/src/mashed_re/Powerup/PowerupSystem.cpp`, between the `raceState != 6`
test and the armed test, RVA-cited line by line. `boxState_[4]` is new state on
`PowerupSystem`, initialised to `1` (what `FUN_004111c0` writes for a slot with a
car), with `SetBoxState` / `BoxState` accessors standing in for the un-ported
`FUN_0045ba00`.

Two hosts supply it:

- `re/tools/pu_replay` feeds the capture's `boxstate` column, carried forward
  across the quiet-gap rows the capture does not emit (a gap means the slot held
  nothing AND had no event; a carried `2` still latches to `3` the same way).
- `TrackRenderer::TickPowerupDispatch` mirrors only `FUN_004111c0`'s 1-or-4 by
  `cars[s].alive`. **The wreck value 2 has no producer in the standalone** and is
  left unwritten rather than invented. Slots without a car were already skipped by
  the armed test, so the `4` changes nothing observable today.

`DumpRow` now emits the real `boxstate` instead of a hardcoded `0`, and maps the
new deactivation to `deact_ra 0x45bc9d`.

## 7. Non-degeneracy — two controls, both run

**33** before, because the port now holds the slot as long as the original does.

## 9. REPORTED AS INERT — a degenerate CLEAN that is not a witness

`s1`, `m1`, `m2` and `s2` each carry a `boxstate == 2` row on a NON-subject slot
(slot 1 / slot 2), each with the capture's own `deact_ra 0x45bc9d`. Replaying
those slots looked like four free witnesses for the `== 2` arm. It is not:
**both** builds report CLEAN there, because `pu_replay` only activates the slot
the `act` column names, those slots got natural pickups through the un-ported
`0x0045bd24` branch, the port therefore emitted **zero** rows, and `pu_diff`
compared nothing. Recorded so it is not mistaken for coverage. Closing it would
mean teaching `pu_replay` to seed a slot from `code_pre`.
