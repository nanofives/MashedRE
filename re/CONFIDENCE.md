# Function Confidence Rubric

Every row in `hooks.csv` carries a confidence label `C0..C4`. Promotion is one-way and gated by **observable evidence**, never by feeling. The `re-classify` skill is the only thing that should mutate a function's confidence — do not edit `hooks.csv` by hand without consulting the rubric.

## Levels

### C0 — Unknown
- The function exists in Ghidra (it has an RVA) but nothing else is established.
- May not even have a name better than `FUN_00xxxxxx`.
- Default state for newly-discovered functions during Phase 1 sweep.
- **Promotion to C1 requires:** at least one of (a) a meaningful name from imports/exports/RTTI, (b) a string xref that hints at purpose, (c) a caller chain that anchors it to a known subsystem entry point.

### C1 — Located
- The function has a tentative purpose drawn from name/strings/xrefs but the body has not been read.
- Belongs to a named subsystem (audio, AI, render, …).
- Calling convention is identified.
- **Promotion to C2 requires:** the decompilation has been read end-to-end and the **shape** of the function (number of args, return type, what it reads/writes) is documented in `re/analysis/<subsystem>/<func>.md`. NO-GUESSING applies — fields and constants are recorded as raw addresses + values, not as semantics.
- **Generated-plate clause (C1→C2; ruling 2026-10-11, user-approved):** a plate written by `re/tools/c2_note.py` (marker `generated by re/tools/c2_note.py`) is accepted as C2 evidence, in place of a hand-read of the decompilation, **only when both hold**:
  1. `re/tools/c2_note_check.py` reports **zero missing callees** for the row against Ghidra's decompilation of the same function (`decomp_pc.py --callees` against a pool slot cloned from the master the plate was generated from);
  2. the generator's lint is clean: no hedge word and no `Purpose` section.

  The plate transcribes the disassembly: every memory access with width and type, every flag consumer with its signedness and setter, every callee with thunks and imports resolved, and every constant cited by instruction address. Other checker items, such as decompiler-composite constants, are not callee misses and do not gate. Open items stay listed in the plate's `## Uncertainties` section and are filed as `[UNCERTAIN U-NNNN]` in `UNCERTAINTIES.md`, one U-id per plate covering every item listed there. The clause covers C1→C2 only: C3 still needs a hand-written `## Purpose` and the C2→C3 evidence below. Pilot and defect classes: `re/analysis/c2_note_pilot_20261011/README.md`.

### C2 — Disassembled
- The decomp has been read and mechanically transcribed: every memory access, every branch, every callee is enumerated.
- Sign and width of every operand is correct (signed/unsigned, 8/16/32/64-bit).
- Field offsets cited (`+0xNN`) for every struct access, even if the struct is not yet named.
- **Promotion to C3 requires:** semantics are inferred and verified. The function has a real name. Every field has a name (or is explicitly marked `[UNCERTAIN]` with the marker recorded in `UNCERTAINTIES.md`). At least one caller and one callee are themselves at C2 or higher (no semantic inferences from islands).
- **Leaf-function exemption (C2→C3 only):** a function with `callees_depth1: []` (pure leaf — no callees) cannot satisfy the "one callee at C2+" half of this rule. The rule is N/A for such leaves *if and only if* the reimplementation has been verified bit-identical against the original on a non-trivial input domain (e.g., a Frida force-call A/B against the live process). Note this exemption applies **only** to the C2→C3 structural rule — it does **not** unlock C4. C4 still requires the canonical-scenario evidence below. Precedent: `0x004c3ac0` `Vec3Magnitude` (2026-05-09; C3 only).
- **Identified-caller clause (C2→C3 caller-half; ruling 2026-06-25):** the "one caller at C2+" half is satisfied EITHER by a caller at C2+, OR by an **identified** caller — one with a recovered real name *or* a documented library role, **including named third-party-library APIs** (e.g. `RpAtomicGetWorldBoundingSphere`). Rationale: the rule's purpose (L23) is anti-*island* — no semantic inferences from unknown context; a *named* caller anchors the leaf to understood context regardless of whether that caller is itself promotable (RenderWare/CRT code stays C1 by library-skip policy but is **not** an island — we know what it does and why it calls the leaf). It is **NOT** satisfied by an anonymous, un-analyzed `FUN_xxxxxxxx`/`LAB_xxxxxxxx` caller with no recovered name or role. This *refines* the earlier 2026-06-25 all-C1-callers ruling: all-C1 callers still block **only when those callers are anonymous**; an identified (named) library caller passes the gate. C4 is unaffected (still requires the canonical-scenario evidence below).
- **Identified-callee clause (C2→C3 callee-half; ruling 2026-07-30):** by symmetry with the identified-caller clause (L25), the "one callee at C2+" half is satisfied EITHER by a callee at C2+, OR by an **identified** callee — one with a recovered real name *or* a documented library role, **including named third-party-library APIs** (e.g. `RpClumpDestroy`). Same rationale (L23 anti-*island*): a *named* callee is understood context, not an unknown island, regardless of whether it is itself promotable (RenderWare/CRT callees stay C1 by library-skip policy but we know exactly what they do). It is **NOT** satisfied by an anonymous `FUN_xxxxxxxx` callee with no recovered name or role, nor by a callee at C0. C4 is unaffected. Precedent: the RpClumpDestroy particle-emitter destructors `0x0041b440`/`0x0041beb0`/`0x0041cb00` (2026-07-30, orch-iter8; sole callee `RpClumpDestroy` 0x004e6e00 is a named RenderWare API held C1 by library-skip).
- **Indirect-dispatch clause (C2→C3 callee-half; ruling 2026-07-31, user-approved):** where a function's **only** callee is an indirect call whose target comes from **caller-supplied or runtime data** — a runtime data table, a function-pointer field, **or a function-pointer passed in as an argument** (`call dword ptr [reg]`, `call [esp+N]`) — the "one callee at C2+" half is **vacuous**, as for a leaf (L24). Rationale (L23 anti-*island*): the call graph here contains no unknown *function* to make inferences from — only a **datum**. Which function runs is a property of the caller's data at run time, not of this function's semantics; the function's own content is entirely the addressing arithmetic that selects the entry.
  **The function-pointer-argument case holds *a fortiori*** (widened 2026-07-31, orch-iter20, from the wording gap recorded in iter19). Where a table or field at least requires establishing *which* memory the function reads, an argument is literally caller-supplied data arriving on the stack: there is strictly *less* unknown state, and the callee's identity is even more plainly a property of the caller than of this function. Nothing in the rationale distinguishes the two, so the earlier "runtime data table or a function-pointer field" phrasing was under-inclusive rather than deliberately narrow.
  **REQUIRED, and this is what distinguishes the clause from a loophole:** the A/B evidence must exercise **the dispatch itself** — a stubbed target that records the arguments it receives — not merely the surrounding code. Otherwise the very thing that makes the callee unknown is also the thing left untested. Verifying that the addressing arithmetic (indirection offset, entry stride, sub-field reads, argument order and extension) reproduces exactly is what stands in for knowing the callee.
- **Installer-caller clause (C2→C3 caller-half; ruling 2026-10-11, user-approved):** the "one caller at C2+" half (L23, as widened by L25) is also satisfied by an **installer**. An installer is a function at C2+, or identified under L25, that installs the target's entry address in a **vtable** or a **function table**:
  - **vtable:** the target is a slot of a table whose start the function writes as a vptr (`mov dword ptr [reg], <table>`, a constructor);
  - **function table:** the function names the table start as an instruction operand in some other way.

  Rationale (L23 anti-*island*): Ghidra's `getCallingFunctions`, which `caller_screen.py` reads, holds only functions that contain a reference to the entry. For a function reached only through a table slot, that reference sits in `.rdata`/`.data`, so no function contains it, and the function reads as an island. It is not one: the installer names the object or table the function belongs to. That is the same anchoring role a named caller plays under L25.
  **Evidence source:** rows of kind `vtable` / `fn_table` in `re/analysis/pointer_callers_<date>.tsv`, produced by `re/tools/pointer_callers.py`. Method and precision are in `re/analysis/pointer_callers_2026-10-11.md`:
  - **99.53%** (1,688 / 1,696) of installer rows agree with Ghidra's own reference database, on held-out targets that Ghidra already references;
  - all 445 rows behind the 2026-10-11 candidates agree on both edges (slot → target and installer site → table start);
  - a 44/44 hand audit by disassembly.

  **NOT satisfied by:**
  1. A row whose `boundary` column is anything but `resolved`. Mashed has no RTTI, so the boundary between two adjacent vtables is visible only through code that references the second start. The walk-back credits a slot to the nearest code-referenced start, and a hidden start between them would hand that table's slots to the wrong installer. A row whose slot lies past a suspected hidden start (`pointer_callers.boundaries()`) is excluded. It may not be the only installer row cited.
  2. `data_orphan` / `text_orphan` rows, which have no installer.
  3. Code-kind rows (`callback_arg`, `rw_register`, `store_mem`, `load_reg`). Ghidra's caller set already counts these, so they add nothing.
  4. The target as its own installer.
  5. An anonymous `FUN_xxxxxxxx` installer below C2, exactly as L25.

  **REQUIRED:**
  - This is C2→C3 only. It does not unlock C4 and does not relax the "verified" half: A/B evidence (path1, or a clause such as L30 where that applies) is still required.
  - The promotion note cites the TSV row: target, slot index and table start, installer site RVA, and the `resolved` boundary verdict.
  - An installer shows that the target is **reachable** through a table. It does not show that the installer calls the target, and the note must not say so.

  **Residual risk:** the boundary test detects a hidden start only when it repeats the two-dword prefix (non-NULL, distinct) of a referenced table. A hidden table with a novel prefix is not detected. On 2026-10-11 it detected none. Reading only slot 0 of each table keeps 18 of the 142 candidates in `re/analysis/pointer_callers_gate_candidates_2026-10-11.tsv`, and that is the worst case.
- **Non-repeatable-function clause (C2→C3 "verified" half; ruling 2026-10-01, user-approved):** some functions cannot be force-called twice for a `run_diff.py` path1 A/B, because one call leaves world state behind that the second call would see (it clones and registers `RpClump`s, re-parents frames, or advances a global cursor). For such a function, the "verified" requirement of L23 is met by a **canonical-scenario hook ON vs hook OFF run** in place of path1, and **only** when every one of these holds:
  1. The reason path1 is impossible is **pre-registered** before the run, with the persistent side effects enumerated and cited by RVA. "It was inconvenient" is not a reason.
  2. The install is witnessed **in process** on the ON arm (the `0xE9` inline JMP read at the RVA) and is absent on the OFF arm. A run that cannot show the hook was live proves nothing.
  3. **Every** write the function makes is compared element-wise between the arms (the objects it creates, their transforms, every global it touches, and downstream counters such as draw totals), and all are identical, on two boots.
  4. Any branch the scenario does not reach is recorded `[UNCERTAIN]` in `UNCERTAINTIES.md`, and the C3 covers only the paths exercised.
  5. `hooks.csv`'s `frida_diff` cell reads `BLOCKED-see-notes`, never a path2 result or a blank, and the notes cite the ON/OFF evidence.
  The clause covers C2→C3 only. It does **not** unlock C4, which still requires the `diff-original` evidence below. Precedent: `0x00448940` `ArcticTrackNodeSlot0` (2026-10-01; clones 24 sea `RpClump`s per call; ON/OFF canonical Arctic run, 25 tile modelling/LTM translations element-wise identical, install witness `0xa5e05be9` vs stock `0x5324ec83`; untested tail branch held as U-9167).
  It is **NOT** satisfied by a function that also calls anonymous *direct* callees — those still gate normally. C4 is unaffected. Precedents: the audio table-dispatch pair `0x005b10a0`/`0x005b10e0` (2026-07-31, orch-iter15; sole callee `call dword ptr [ecx]` off an 8-byte-entry table, verified with `vtable_table_dispatch` recording `(a1, aux16, a4)` across four entry indices) — *table* case. `0x005af200` `AudioChainWalk` (2026-07-31, orch-iter19; the dispatched callback is a **function-pointer argument**, verified with `stub_dispatch_observe` recording call sequences `b0` / `b0,b1` / `b0,b1,b2` over one-, two- and three-node chains, so link *order* is verified and not merely the call count) — *argument* case, promoted under the widened wording above.

- **Replay clause (C2→C3 "verified" half; ruling 2026-10-11, user-approved):** the "verified" requirement of L23 may be met by an **offline replay of real recorded calls** in place of a path1 A/B. The instrument is `re/tools/veccap/record_race.py` (records the original during a canonical scenario, hooks OFF) plus `re/tools/veccap/replay_c3.py` (runs the original's bytes AND the port's machine code in one Unicorn address space on the recorded memory). It holds **only** when one `replay_c3.py` run ends in `VERDICT,GREEN`, which requires every one of these:
  1. **Live calls.** At least 100 **distinct** input vectors recorded from the original during a canonical scenario. Every leg-1 value is what the game itself computed: out buffers read at return, ST0 read with `fst` at return. Repeats do not count (the menu fed `0x004c3ac0` 301 identical zero vectors on 2026-07-16, which is 1 vector). Synthetic vectors never count toward this gate.
  2. **Three-way equal on every call:** live == emulated original == emulated port, for the return value and the out buffer, with both bodies run under the **recorded** x87 control word and MXCSR. The race loop runs PC_24 (CW `0x007f`), and a port measured at another precision is not measured at all (precedent below).
  3. **Write set and stack cleanup equal on every call:** every non-stack byte either body writes (address to last value) and the ESP delta at return. Writes into the port image's own data are counted and reported, not compared.
  4. **Nothing the instrument cannot vouch for:** zero reads outside the declared state (the call's buffers, read-only image sections, captured RW regions), zero unmapped accesses, zero port imports other than the modelled `VirtualQuery`, zero emulator errors. Any of these makes the run `VOID`, never `GREEN`.
  5. **Branch coverage of at least 90%** of the original body's jcc sides (taken and not-taken counted separately, body found by recursive descent from the RVA, callees not counted), over the live calls. Every uncovered side is recorded `[UNCERTAIN]` in `UNCERTAINTIES.md`, and the C3 covers only the paths exercised.
  6. **No x87 transcendentals.** A body whose static direct-call closure, or whose execution on either side, reaches `FSIN`/`FCOS`/`FSINCOS`/`FPTAN`/`FPATAN`/`F2XM1`/`FYL2X`/`FYL2XP1` is `REFUSED`: QEMU computes those through host double maths, not the x87 microcode. Screen any RVA with `replay_c3.py 0x<rva>`.
  7. **The port under test is the body the hook installs:** the export, or the `<export>_impl` a ShadowAB wrapper dispatches to, compiled with the `.asi`'s flags (`/EHsc /W3 /O2`, plus `/arch:IA32` for the TUs in `mashedmod/x87_tus.txt`). An `--x87-extra` or `--force-cw` run is an experiment and never evidence.
  8. **Controls on file from the same tool version:** the VECCAP-2 control `0x00566200` reads `RED` (`--synth`), and a `--wrong-port` mutation run on the promoted row's own bundle reads `RED`.
  `hooks.csv`'s `frida_diff` cell points at `log/diff/<rva>_<name>.replay.csv`, and the bundle `re/replay/veccap/<rva>_<name>.json` is committed.
  The clause covers C2→C3 only and **never unlocks C4**: no hook was live while the calls were recorded, so it shows nothing about the installer or about the canonical scenario with the hook ON. C4 still requires the `diff-original` evidence below. Every other C3 requirement still applies (real name, plate, the anti-island halves, `RH_ScopedInstall`), and so does the dual-copy clause below: the replay measures the TU in `file`, so a row with `exe_file != file` gains nothing for the exe.
  Precedents (2026-10-11, branch `tools/replay-as-c3`): `0x004c3ac0` `Vec3Magnitude` GREEN on 1500 calls / 692 distinct / 2 of 2 jcc sides, and `0x004c3b30` `FastSqrt` GREEN on 2400 / 494 / 2 of 2, both already C4 so re-verified only. `0x00546c50` read `RED` on 243 of 1200 live race calls (1 ULP): the SSE2-compiled port cannot follow PC_24, and the same calls replayed at PC_53 agree 1200/1200. This is the first finding the clause made visible that an earlier in-process A/B did not (`log/shadow_ab/` 48/48). Resolved the same day by user ruling: the body moved to its own TU `Collision/RwpSolverMath2QuatY.cpp`, compiled `/arch:IA32`, which reads GREEN 1200/1200 at `0x007f` (C3 kept; SSE2 record `log/replay-c3/experiments/00546c50_rwp_mat2quat_y.sse2_RED.replay.csv`). Controls: `log/replay-c3/negctl/`.

### C3 — Understood
- The function's purpose is stated in plain prose at the top of `re/analysis/<subsystem>/<func>.md`, with citations.
- A reimplementation has been written in `mashedmod/src/mashed_re/`.
- Build is clean.
- The function is hooked through `RH_ScopedInstall` and runtime-toggleable.
- **Promotion to C4 by the frida route requires:** the `diff-original` skill has produced a clean Frida CSV diff between original and modded behavior on at least one canonical scenario, with the hook installed. No stubs in the implementation. (The two static routes, `match` and `libid`, are in "C4 routes" below. They do not need C3 first.)

- **Write-set leg for C4 (user decisions L-38, L-40, L-54, 2026-10-27..29):** a function that stores outside its
  own frame needs, next to the clean race diff, a write-set compare against the original that actually compared
  memory:
  - **Heap writers:** a heap-tracked shadow leg (`MASHED_SHADOW_PRIVATE=1`) that is CLEAN with **more than 0 heap
    pages compared**, or a CLEAN region compare of the written struct with heap tracking on. A leg that compared 0
    pages is not evidence (L-38: four rows demoted 2026-10-27 because tracking was off).
  - **Writers whose sampled calls land only in the caller's stack, or write nothing in the sampled calls:** stay C3
    until a scenario makes them write to compared memory (L-40; e.g. a car-contact scenario).
  - **Statically empty write-set:** a function with no store outside its own frame (a pure wrapper; checked
    statically, e.g. the SCOPE store list) can reach C4 on a clean race diff alone, because there is nothing to
    compare (L-54). Its callee's level does not cap it. Precedent: `0x0056bb30` (2026-10-29, wraps `0x0056ba30`).

### C4 — Verified (the reverse engineering is certified)
- C4 certifies the **reverse engineering** of the function: our reconstruction is shown equal to the original, either
  in behaviour (frida route) or as compiled source (`match`, `libid`). Since L-93 (2026-11-07) C4 makes **no claim
  about the port**: whether `mashed_re.exe` compiles that reconstruction, and whether the game calls it, is the port
  axis (section "Port axis" below).
- The function is canonical reference material; lower-confidence callers can lean on it.
- `ROADMAP.md` (v4) defines the function Definition of Done on both axes. C4 is the RE-axis one.

**What C4 meant before 2026-11-07 (history).** From the first rubric to L-93, C4 certified the port as well: the frida
route needed the hook live in the canonical scenario, and the byte-match routes (2026-10-31) needed the matched source
to be the exe's only body (old match rule 2), the merge-train gates unchanged after the swap (old rule 3), an exe caller
of the swapped body (L-68, refined by L-84 and L-89), and for `libid` the port compiling the vendored source (which kept
qhull waiting on L-73). L-93 (Mariano, 2026-11-07, option B, `log/orch/DECISIONS.md`) separated the two questions, the
way SimGolf does (`SimGolf/re/CONFIDENCE.md`; SimGolf also asks for a C3 hook, Mashed does not). The port rules were not
dropped: they moved, unchanged, to the port axis. Rows promoted before L-93 keep their C4.

### C4 routes (L-93, Mariano 2026-11-07; static routes first written 2026-10-31)

A row is C4 by **any one** of three routes. Each route is recorded in `hooks.csv` `notes` (`c4=match`, `c4=libid`, or
the frida CSV) and in the `re-classify` evidence fields. Tools: `re/tools/match/`, batch gate `re/tools/c4_reclass.py`.
Measurements behind the static routes: `verify/matchpilot_20261030/RESULT_MATCH-PILOT.md`,
`verify/libidentity_20261030/RESULT_LIB-IDENTITY.md`.

- **frida (unchanged).** A clean `diff-original` run on a canonical scenario with the hook installed, plus the
  Write-set leg (both above, under C3).
- **`match` (game code).** C4 when **all** of these hold, and nothing else is asked:
  1. The reconstructed source is **byte-identical** under `re/tools/match/match.py` (relocated operands masked; the
     whole-symbol `--bytes` compare reports no differing byte, and the instruction compare is 100% or the original's
     Ghidra body is shorter than the symbol) with the recorded compiler, XP DDK `cl` 13.00.9176 / `c2` 13.00.9178
     (`tools/vc7ddk`, `// TOOLCHAIN ddk`, the default), and the flags recorded in the source (`// FLAGS:`; game code
     `/O2 /GS /Ob1`, as C, x87; `/G5` breaks game code).
  2. `re/tools/match/relocheck.py` reports **OK** for that function. `match.py` masks every relocation, so 100% alone
     does not show that each global, callee or constant is the right one: MATCH-S02 found two sources at 100% that
     stored to swapped arrays (0x0040b250, 0x0040b810; `verify/matchs02_20261031/RESULT_MATCH-S02.md`). relocheck
     resolves each relocation (`MGLOBAL` names, `FUN_<rva>` callees, Ghidra address-suffixed data names such as
     `DAT_<va8>` / `_DAT_<va8>` / `PTR_..._<va8>` / `s_..._<va8>`, own constants and strings) against the original's
     operand and lists the rest. Named data has been checked since 2026-11-11 (MATCH-EXACT-DATA): before that, two C4
     sources at 100% loaded swapped float operands (0x00414060, 0x004030d0;
     `verify/matchexactdata_20261111/RESULT_MATCH-EXACT-DATA.md`). It lists the rest (imports, CRT helpers, file-static data) as unchecked by name. Those names go in the
     evidence.
  3. The source is **not a naked inline-asm transcription** (`__declspec(naked)`), and its body is **not only inline
     `__asm`** inside a compiled C frame (SimGolf G26 rule, 2026-11-02: one `__asm` block plus declarations and a
     `return` is a transcription too). Both match by construction. Inline `__asm` inside a body that does real C work is
     fine.
  4. No `STUB` marker in the function body.

  Removed from this gate by L-93: the exe uses the source as its body, the exe calls it, the gates are unchanged after
  a swap. Those are port-axis facts now.
- **`libid` (vendored or linked library code: Lua 4.0, qhull 2002.1, the DDK CRT, libpng 1.0.12, zlib 1.1.3).** C4
  when the function is **identical** to one function of the library object, or of the library source compiled with its
  recorded flags (`re/tools/match/libmatch.py`: every byte equal except relocation sites, relocations into the same
  function checked). The libmatch status must be `identical` (or `identical-unlisted`, the same identity at an address
  that had no row yet) with **one** candidate: an `identical-ambiguous` row (the same bytes as several library
  functions) does not name the function and is not C4. Recorded builds: Lua `/O2 /Ob1 /G5`, qhull `/O2 /G5`, libpng
  and zlib `/O2 /G5`, CRT = the DDK `libcmt.lib` member (`@comp.id` in the evidence). The old clause "and the port
  gets the function from that same vendored source" is removed by L-93 (port axis).

**What `match` and `libid` evidence covers.** The Write-set leg is a **frida-route leg** only: it exists because a
clean race diff cannot show stores that land outside the sampled memory. Byte identity covers the function's **own**
instructions: identical bytes perform identical stores for identical inputs, and relocheck checks the address behind
each named global, callee and constant. It does **not** cover: (a) callees, which keep their own level (relocheck proves
the call goes to the right RVA, not what is there); (b) relocations relocheck lists as unchecked (imports, CRT helpers,
file-static data), named in `notes`; (c) anything about the port (its body, its globals, its callers), which is the
port axis.

**Batch promotion.** `py -3.12 re/tools/c4_reclass.py batch --tsv <rva,route,evidence> [--apply --result <RESULT>]`
recompiles every `match` source and re-runs relocheck at promotion time, checks the `libid` TSV status, refuses each row
that fails a criterion above (by name) and writes the rest in one transaction, one CHANGELOG line per row. Usage:
`re-classify` skill, "Batch C4 (L-93)".

## Port axis (`hooks.csv` `port` column; L-93, 2026-11-07)

The port axis records what `mashed_re.exe` does with an RVA. It is measured separately from C0..C4 and is what the
project Definition of Done (P-DoD) counts (`ROADMAP.md` v4).

- **`port` column** (derived, built by `scripts/backfill_port.py`, step C4R-PORTCOL; regenerate it, do not hand-edit):
  - `none`: `mashed_re.exe` compiles no body for the RVA.
  - `body`: the exe compiles a body for the RVA, and no game path in the exe calls it.
  - `called`: the exe compiles a body for the RVA and a game path in the exe calls it.
- **Rulings that now decide the port column, not C4** (text unchanged, scope moved by L-93):
  - **Old match rule 2:** a matched source swapped in is the RVA's only body (the `lint_rva_bodies.py` rule), in both
    targets where the RVA is hooked, physics TUs listed in `mashedmod/x87_tus.txt`.
  - **Old match rule 3:** after any body swap the merge-train gates are unchanged (`gctrl.ref` / `b.ref` in
    `re/orchestrator/merge_train.json`). A swap that moves a gate hash is a real port divergence: file it as an L-n
    decision. This still binds every merge; it no longer binds C4.
  - **L-68 (callerless bodies, 2026-10-31):** a body with no exe caller (`exe-callers=0`) is `body`, not `called`.
    Older notes reading `match evidence: identical, swapped, exe-callers=0; C4 when a caller lands (L-68 ruling)` are
    history: those rows take `match` C4 under L-93 when the route holds (C4R-MATCHBATCH), and the old demotion of a
    callerless `match` C4 no longer applies.

## Which copy the evidence covers (clause added 2026-09-29)

**C3/C4 evidence names the copy it covers.** The project builds two targets from two
different source lists (`mashedmod/exe_sources.rsp`, `mashedmod/asi_sources.rsp`), so one RVA
can have two bodies. Every `RH_ScopedInstall` gate and every `diff-original` run above is
defined over the **`.asi`** — in `mashed_re.exe`, `HookSystem::Register` is an empty function
(`mashedmod/src/mashed_re/Stubs/HookSystemNoOp.cpp:19`), so registration proves nothing there.

The `file` column of `hooks.csv` names the copy the evidence measured (by convention, the
`.asi` copy). The `exe_file` column names the TU compiled into `mashed_re.exe` that carries a
body for that RVA — empty when the exe has no port.

A row is C3/C4 **for the shipping exe** only if **either**:

- `exe_file` is empty or `exe_file == file` — one body, so the evidence covers what ships; **or**
- the exe copy has **its own** evidence, cited in `notes`.

When `exe_file != file`, the row's level describes the `.asi` copy only. It is **not** a claim
about `mashed_re.exe`, and it must not be cited as one in a parity, D3-criterion or
Definition-of-Done argument.

Two corollaries, both learned the hard way:

- **Fixing the exe copy by reading is not evidence for the exe copy.** A copy edited to match
  the verified body has been *re-verified by reading*, which is a C2-grade statement about the
  exe. It earns C3/C4 for the exe only through the normal gates, run against that copy.
- **A "fixed" exe copy does not restore the row.** Demotion is judged per copy, not per RVA.

ROADMAP phase D4 carries the burn-down: consolidate each pair into ONE shared TU judged
against the original, at which point `exe_file == file` and this clause stops costing anything.
`mashedmod/build.bat` runs `scripts/lint_rva_bodies.py` before the compile step to stop new
pairs appearing; `re/tools/dual_copy_allowlist.txt` is the shrinking list of known ones.

Precedent and the full finding: `re/analysis/DUAL_COPY_AUDIT_2026-09-29.md`,
`re/analysis/DUAL_COPY_FIX_2026-09-29.md`.

**Scope (L-93):** this clause is about the frida route, whose evidence is measured on a copy. A `match` or `libid`
C4 certifies the reconstruction, not a copy in either target, so it is neither a claim about `mashed_re.exe` nor
weakened by a second body. Which bodies the exe has is the port axis.

## Demotion rules

A function is **demoted** automatically when:
- A diff regression is observed (C4 → C3 until re-verified).
- A `match` or `libid` C4 whose cited evidence no longer passes the route (the source was edited and no longer
  recompiles byte-identical, relocheck turns BAD, the identity turns out ambiguous) drops to the level it had before.
  `c4_reclass.py batch` on the cited source shows it.
- A struct it depends on changes shape (any function touching that field at C3 → C2).
- An `[UNCERTAIN]` it depends on is upgraded with new contradicting evidence.
- Its **shipping-exe copy is shown to differ in behaviour** from the copy the evidence measured
  (2026-09-29 clause above): the row drops to the level the exe copy's own evidence supports —
  usually C2, since the decomp has been read but nothing has measured that body.

Demotions are loud — emit a row in `re/analysis/CHANGELOG.md` so we don't lose track of regressions.

## Anti-patterns

- Promoting on "this is probably what it does." Ban.
- Skipping levels (C0 → C3). Ban — every level's evidence must be on file.
- Promoting an island. If callees are C0 and the function reads an unknown global, it cannot be C3.
- Promoting because the build compiles. C3 requires reasoning about behavior; C4 requires a frida diff with the hook live, a byte match (match.py + relocheck OK) or a library identity. Compile-passing alone gets you nothing.
